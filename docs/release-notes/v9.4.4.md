# BOSS v9.4.4

**Release Date:** 2026-08-08

Three resource tiers keep the process well below the PartitionAlloc wall that killed 9.4.0, and the organisation web pages shipped in 9.4.3 are brought onto the app's Blueprint identity with their contrast measured rather than eyeballed. The organisation half also gains an optional website on the request form, gives boss-organisation members a legible role, and repairs a nondeterministic `primary_role` claim that a signup between two deployments could write permanently.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

> **Known incomplete**: fluck-browser does not yet read `boss.browser.hibernationIdleMs`, so the per-tier hibernation timings are published to plugins but not in force. No user-facing string mentions them.

## Highlights

- **Lite and Ultra Lite, and no tier takes a feature away.** A Chromium renderer limit (4 at Lite, 2 at Ultra Lite), tier-aware hibernation timing published to plugins, and the background sampler off at the tightest tier. Every plugin still loads and every tab still opens at every tier. Windows defaults to Lite, and deliberately not Ultra Lite: the renderer limit is a security control as much as a memory one, and at a limit of 2 a browser used for real work puts very nearly every tab in one process, widening the blast radius of any single renderer compromise to every site open in it. Elsewhere the tier auto-selects by installed RAM, with a live watchdog reading real available memory per platform rather than the JDK's free-pages number, which reports 0.7% on a healthy 128 GB Mac. Settings and View > Resource Mode both report what is actually running rather than what is selected (#141)
- **Contrast is measured, not eyeballed, and the measuring is the part worth keeping.** The organisation pages now mirror `BossBlueprintColorScheme` / `BossBlueprintLightColorScheme` as CSS custom properties, with light mode honoured because the in-app browser bridges the host theme to `prefers-color-scheme` - without it, Blueprint Light users got a dark page inside a light app. The light theme rendered fine and had six sub-AA pairs in it: hints at 2.54:1, the admin pill at 4.27:1, both banners near 4.1:1. None of that is visible to someone who already knows what the words say. `contrast.test.ts` parses the tokens out of the real stylesheet and holds 28 pairs across both themes, compositing surfaces from the real declarations - the `--token-wash` rgba, the banner tints, the danger-button hover fill - so a change to either moves the test with it. Four rounds of review each found a surface the matrix did not list, and each one was a live failure: the wash behind every role name and slug, the doubled wash a `.danger` button is always read on, all six status borders (2.11:1 on ink, 1.33:1 on paper against a 3:1 floor), and `--line-strong`, the edge of every input and select, at 1.63:1 (#148)
- **Cloudflare was turning every member email into the words "email protected".** An admin opening the roster could not answer the one question the page exists for. Not our markup: `api.risaboss.com` sits behind Cloudflare, whose Email Address Obfuscation rewrites any address in an HTML response into a `__cf_email__` anchor plus an injected decoder script, and our CSP is `default-src 'none'` with `script-src` nonce-only, so the script is blocked and the address never decodes. Two features each behaving correctly, silently destroying the content. Fixed in the repository rather than by turning the feature off in a dashboard or by widening the CSP. The first fix was per-field and the failure is per-response - a join request reading "reach me at me@corp.com" broke identically through `request_message` - so one `<!--email_off-->` region now wraps the whole page (#148)
- **A signup between two deployments got a permanently nondeterministic role claim.** `handle_new_user` inserts the boss-organisation role and the global `user` role in one transaction, and both used `now()`, which is `transaction_timestamp()` and constant however deeply nested the call is - so two `user_roles` rows carried an identical `assigned_at`. `get_user_roles_for_hook` aggregates `ORDER BY assigned_at` and the access-token hook takes element 1 as `primary_role`; PostgreSQL sorts are not stable, so on a tie the winner is plan-dependent and a re-plan after ANALYZE can flip a displayed role with no data change. Not an escalation, since permissions come from the full array. `clock_timestamp()` stops new ties, and a second migration nudges the organisation row forward by one microsecond wherever it still ties, moving the organisation role and never its peer so the intended order is restored rather than an arbitrary winner picked (#148)

## Features

- **perf**: Lite and Ultra Lite resource modes. Three tiers - Full, Lite, Ultra Lite - differing in Chromium renderer limit, hibernation idle timing published to plugins as `boss.browser.hibernationIdleMs`, and whether the background performance sampler runs. Auto-selection reads installed RAM against ceilings of 16 GB (Lite) and 8 GB (Ultra Lite), overridable through `BOSS_RESOURCE_LITE_GB` / `BOSS_RESOURCE_ULTRALITE_GB`, with Windows taking Lite as a platform default. A `MemoryPressureWatchdog` samples real available memory per platform, since Linux `MemFree` excludes the page cache and almost any threshold against it produces false positives, and offers to tighten the tier for the next launch through a notice dialog. Exposed in Settings and in View > Resource Mode, both reporting the running tier rather than the selected one (#141)
- **organisation**: restyle the web pages to Blueprint, and make the palette provable. The pages were still on the previous identity, amber `#F2A93B` on `#1a1a1a` copied from the passkey pages, while the app default moved to Blueprint months ago. Signal is the fill and signalText is the glyph here too: `#0F5BFF` is 3.5:1 on ink, which is a border or a filled button and not a word, so accent-coloured text uses the light-blue family and an emphasised pill is a wash behind readable text. `render-preview.ts` renders nine pages from fixtures with no database, covering every state that changes the markup - the first version skipped `newInviteUrl`, `inviteOnlyPage` and `errorPage`'s action, which is how a dead `.highlight` rule survived the visual check built to catch exactly that (#148)
- **organisation**: an optional website, asked for at request time. The domain and the website do different jobs: the domain governs who may join (verified by DNS, it lets matching addresses find and join), the website is identity and grants nothing. Scheme-restricted to http and https in three places, because this value is filled in by any authenticated user before any review and is rendered as a link on pages members read, so a `javascript:` or `data:` URL would be stored XSS with a self-service entry point - the RPC refuses it with a readable sentence, a column CHECK refuses anything bypassing the RPC, and `attrUrl` refuses it again at render. `attrUrl` takes `["http", "https"]` for this one link and no schemes everywhere else, where the default of same-origin-path-only is right. Adding a defaulted parameter is not a replacement: `CREATE OR REPLACE` matches on the argument list, so the three affected functions are dropped and recreated with their REVOKE/GRANT re-applied. The parameter sits before `p_actor_id` to keep impersonation last, which shifts every positional caller - the pgTAP suite caught that immediately with eight failures (#148)
- **organisation**: give boss-organisation members the user-kind role. Requested after the roster showed a blank role column for every member but the owner. The seed had set `auto_assign_member_role = false` on the reasoning that a `user_roles` row per user lengthens every JWT for zero extra permissions, which is still true and is being overridden deliberately so membership is legible from a user's roles. Cost recorded rather than rediscovered: every active member gains a row and organisation role names ride in the existing `user_roles` claim, so every token grows by one entry; no permission changes. Four parts, because flipping the flag does nothing on its own - the UPDATE matches zero rows on a fresh deployment, `ensure_boss_organisation()` hardcoded false and would silently undo it, and `handle_new_user` inserted the membership row directly without ever calling `assign_org_member_role_internal`. Pending and invited members are excluded from the backfill, since granting them a role hands out standing that approval exists to gate (#148)

## Bug Fixes

- **organisation**: keep Cloudflare from rewriting member emails into "email protected". One `<!--email_off-->` region wraps the whole page rather than a list of fields, because Cloudflare rewrites any address it finds and not only ones from a column named email. Values are still escaped - the comments tell a proxy to skip a region, they are not an escaping mechanism, and a test pins that. Three guards on the layout, mutation-verified. Source-scanned rather than output-scanned, because the failure happens at the edge *after* we render: our own HTML is correct, and nothing assertable about our output would have caught it (#148)
- **organisation**: six sub-AA pairs in the light theme, then three more surfaces the matrix never listed. The binding surface for banner text is the 10% status tint, which on a light theme is darker than the card, so solving against the card left both banners failing. `.pill.mono` and `.slug` paint on `--token-wash`, where three pairs stacked at 4.36:1, 4.09:1 and 3.84:1 while the suite reported green. Every `.danger` button lives in a table cell, so hovering it also hovers the row and the label is read on a doubled wash every time: 4.09:1 on paper, 4.34:1 on ink. All six status borders were 45% of the dark hue in both themes. And `--line-strong`, the edge of every input, select, textarea, secondary button and table header, sat at 1.63:1 on ink - it matters more than a card edge, because the control's own fill is nearly the card colour in both themes, so that line is the only thing marking where the control is. Mutation-verified in both directions (#148)
- **organisation**: `primary_role` could be either of two roles for the same user. `clock_timestamp()` in `assign_org_member_role_internal` stops new `assigned_at` ties, and `20260806020000` repairs the rows already written - the previous migration's header claimed existing users were unaffected, which is true of users predating the backfill and false for anyone created between the two deployments, precisely the population the fix was for. Idempotent, and correct whether the affected population is zero or everyone in that window. The migration also RAISEs a warning naming any pre-existing `secret_shares` row targeting `boss_org_user`: the role was held by nobody before this release, so anything keyed on it was inert, and a share targeting it now reaches every active member (#148)
- **organisation**: a bad website in the admin form discarded everything submitted with it. `update_organisation_settings` had no website validation, so the only guard was the column CHECK, which raises 23514 and aborts the whole UPDATE - typing "acme.com" into the settings form threw away the name, description, visibility, join policy, publish policy and the auto-assign checkbox in the same submission, and the page could only say "The change was refused", naming no field. One `validate_website()` both RPCs call, plus a re-check on `create_organisation_internal`'s write path, and the route validates too so the operator gets a dedicated `invalid_website` message instead of the generic refusal the database-side check was added to replace. Deliberately a second copy rather than forwarding RPC text, since the fixed-key vocabulary is what stops caller-controlled strings being reflected onto the page. Six pgTAP assertions cover the admin path including that it fails closed (#148)
- **organisation**: an approver could not see the website they were approving. `list_organisation_requests` never projected it, while the entire threat model is that any authenticated user supplies this value and it becomes a link on a page other members read - review is the control between those two facts, and the queue was not showing the field (#148)
- **organisation**: the mobile table rule deleted content, and the fix only worked with a pointer. Hiding every column past the third did not make the table fit, it removed "Joined" and "Permissions" from the reader's view. The first replacement put `overflow-x` on `section.card`, which made the columns reachable by dragging and unreachable from a keyboard, because a scroll region needs focus to be operable and these tables hold nothing focusable - the same content loss in a different modality - and made every card a scroll container in both axes, so headings scrolled sideways with the table. Each of the seven tables now has its own wrapper with `role="region"` and a name, and `tabindex` only where the content is not already focusable, since the five admin tables hold selects and buttons and would otherwise add an empty tab stop each to the page with the most controls. A guard asserts every `<table>` in `views/` has a wrapper (#148)
- **organisation**: the highlight on the one-time invite card had never rendered. `section.card` sets `border-color` at specificity (0,1,1) and a bare `.highlight` is (0,1,0), so the card won - and that card displays a live bearer token exactly once, which is the card that most wants singling out. The round-two CSP fix had shipped with no visible effect for the same reason, its markup reading `class="card" class="highlight"` where a parser keeps the first attribute and discards the second (#148)
- **organisation**: smaller page fixes. `focus-visible` instead of `focus`, so a mouse click stops painting the ring the keyboard user needs; `prefers-reduced-motion` honoured; checkboxes take the accent; the active tab carries `aria-current`; `role="status"` removed from banners rather than left as a decoration, since a live region fires on change and these are server-rendered into the initial document. The role select carried the page-wide `width:100%`, so inside a table cell it filled the cell, pushed its own Assign button onto a second line and left Remove floating at a different height. A stat value that is a phrase is not a figure: "request to join" at the numeral size dominated a row whose other values were "89" and "2". The two stat sizes also had different line boxes, so captions in one row sat ~6px apart. A 500-character website has no break opportunity and is its own link text, so `overflow-wrap` on the link (#148)
- **organisation**: `DROP FUNCTION` takes the comment too. `20260807000000` re-applied its grants and re-added one comment, silently losing `create_organisation_internal`'s and `update_organisation_settings`' - including the "service_role ONLY: it accepts an arbitrary owner" warning, which is the line a reader most needs. Restored. `validate_website` was also the only helper in the schema with an OWNER and no REVOKE/GRANT, so it defaulted to PUBLIC and was anon-callable; impact nil since it is pure, but the convention is what makes a real exception visible (#148)
- **organisation**: `20260808000000`'s header described a guard it did not add. It claimed the website check "now lives in one place both RPCs call, and `create_organisation_internal` re-checks on the write path"; that function was never redefined and still did a bare `NULLIF` into the INSERT. Unreachable today only because approval passes a value that already cleared a textually identical CHECK on `organisation_requests`, but the function is service_role-callable directly and such a caller got a raw 23514 propagating out of `approve_organisation_request` as an unhandled exception instead of the `{success,error}` object every other refusal there returns (#148)
- **focus mode**: hover-to-reveal now starts off on Windows, where the browser owns a foreign native window that swallows the pointer events the feature needs (#141)

## Improvements

- **organisation**: drop the status fills nothing paints. `--panel` was never painted, and `--ok` / `--warn` / `--alert` became unused once their text uses moved to the text-safe variants and the danger hover border took `--alert-border`. Removed rather than kept as palette completeness: an unused vivid status colour is precisely what the next person reaches for as text, and `color: var(--ok)` is 3.43:1 on a white card, which is the bug this change set closed. With the fills gone, the text-safe variants are the only reachable status colours (#148)
- **tests**: three vacuous guards, in the file whose whole subject is guards that look like they work. `organisation_website_test` cleared the website with `''`, asserted NULL, then passed NULL and asserted NULL again, so "a NULL leaves it alone" could not tell leave-alone from clear - the exact confusion the `CASE WHEN` exists to prevent. The token-count floor counted the *merged* palette, and light is built as `{...dark, ...light}`, so a light block truncated to zero tokens still reported the full dark count and the guard could not fail for the palette it was added for. And the repair assertion in `boss_org_member_role_test` proved only that the tie was gone, not the direction of the nudge, which is the whole point of moving the organisation row rather than its peer. Also recorded: a mutation run grepped only for "# Failed test" and found none, which read as "the test does not catch it" - the run had aborted and printed no failure lines at all, and absence of a failure marker is not evidence of a pass (#148)
- **organisation**: `scrollable()` is used by `admin.ts` rather than hand-rolled five times, `.linkish` is gone as a duplicate of the bare `a` rule it shadowed, both website guards use a local rather than calling `validate_website` twice, and the preview fixture's invalid `publish_policy` no longer renders that select unselected in every preview (#148)
- **organisation**: checked and cleared rather than assumed, both downstream consumers of the two RPCs that gained a `website` key are safe - the organisation plugin decodes with `ignoreUnknownKeys`, and the Toolbox parses untyped through `parseToJsonElement` and reads keys by hand, so neither can throw on it (#148)
- **tests**: 159 Deno tests and 414 pgTAP across 16 files for the organisation work, `deno check` over every file and lint clean; 11 new test files for resource modes covering tier resolution, per-platform memory parsing, the watchdog, the Chromium switches, the menu, the settings section and every user-facing string (#141, #148)
