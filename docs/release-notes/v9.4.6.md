# BOSS v9.4.6

**Release Date:** 2026-08-09

The integrated browser now reports how BOSS is used with websites - page views, dwell against active time, navigation depth and in-page interactions - through a privacy boundary that turns a full URL into an eTLD+1 registrable domain and an in-page collector written never to read page text in the first place, with `BOSS_BROWSER_TELEMETRY_DISABLED` as a one-variable off switch. And Windows comes up as a plain browser on risalabs.ai, with no panel opening by itself.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **Browser telemetry that answers "how are users interacting with websites" without recording what was on the screen.** `BrowserAnalytics` is the privacy boundary: a full URL goes in and only a registrable domain comes out, while loopback, bare IPs and single-label intranet names report nothing at all. `BrowserVisitTracker` does per-tab engagement accounting, because wall-clock is not engagement - a tab left open on a portal overnight reports a huge dwell and near-zero active time, and reporting only the former would rank it the most-used site in the product. The in-page collector reads a fixed set of structural attributes in one `describe()` function and nothing else: no `textContent`, value, placeholder, `aria-label`, id, `className`, `href` or clipboard. That is a reading restriction rather than a filtering one, so page content cannot leak through a bug in a later sanitizing step - it is never in a variable (#98)
- **Windows comes up as a plain browser page.** A new "Browser Only" workspace on `https://www.risalabs.ai`, listed on every platform but the default only on Windows, replaces the terminal-first Claude Code layout there. The startup effects that opened the Codebase and Run Configurations panels now route through one seam gated by `StartupPanelPolicy`, which is off on Windows - those two are the only panels the host ever opens unasked, and no bundled plugin opens its own at registration, so nothing opens by itself. Everything is still one sidebar click, menu item, deep link or CLI command away (#158)
- **Focus mode switches each edge independently, and keeps the sidebars on Windows.** It used to clear the top bar, both sidebars and the bottom bar together; `hides(edge)` is now the single question the chrome asks, with a switch per edge in Settings. Windows keeps both sidebars by default for the same reason auto-reveal is off there: reveal is driven by Compose pointer events on edge strips, and the HARDWARE browser surface owns those pixels, so hiding a sidebar would be a one-way door with no hover to bring it back (#158)
- **The telemetry kill switch is a real off switch.** `BOSS_BROWSER_TELEMETRY_DISABLED=true` (also `1` / `yes` / `on`, or the `boss.browser.telemetry.disabled` system property) gates the single `publish()` every browser event goes through, *and* stops the collector script being injected into pages at all. It first only skipped injection, so every `PAGE_VIEWED`, `PAGE_LEFT` and `TAB_*` event still reached the bus - an operator who sets a variable by that name means all of it, and silence is the wrong direction for a privacy control to fail in (#98)

## Features

- **browser**: navigation, engagement and interaction telemetry, all publishing through `BrowserAnalytics`. `BrowserVisitTracker` tracks dwell against active time, navigation depth within a run on one site, and how the navigation was triggered, one instance per handle so there is no registry to leak when a tab dies. `BrowserInteractionScript` plus `BrowserInteractionBridge` collect clicks, rage clicks, scroll depth, field focus, form submits and copy/paste. `window.__bossInteraction` is reachable by any script on the page, so the host re-validates everything and drops unknown interaction types, oversized payloads and over-long batches. Page-view emission moves out of `UrlHistoryManager` to the navigation handler, which is the only place that knows which tab navigated - dwell and depth are per-tab and `addUrl` has no tab identity, so tracking there would interleave every tab's visits into one bogus timeline (#98)
- **workspace**: a "Browser Only" workspace, and a Windows default that reaches installs already on disk. `~/.boss/workspace-settings.json` is written on first launch with `encodeDefaults = true`, so every existing Windows install already holds `workspace-claude-code` and a changed default would never be read. A `settingsVersion` field drives a 0 to 1 step that repoints a Windows install only if it is still sitting on the old universal default; an explicit choice, including "none", is preserved and stamped. The field defaults to 0 rather than the current version on purpose - every file written before it existed is missing the key, and defaulting to the current version would silently skip this and every future migration (#158)
- **focus-mode**: `hideTopBar`, `hideLeftSidebar`, `hideRightSidebar` and `hideBottomBar`, each a switch in Settings, with the four copy-pasted delay and grace-period effect pairs collapsed into one `EdgeRevealEffects` over a per-edge state object - which is what let the two detekt suppressions on `rememberFocusModeReveal` be deleted rather than re-baselined. A hover strip is now laid out only for an edge that is actually hidden, since a strip is an invisible band as wide as the reveal offset and one on a visible edge is dead space over live content (#158)

## Bug Fixes

- **windows**: the browser-only default never reached a fresh install, the case it was written for. It applied only from a `LaunchedEffect` gated on a non-empty project path, and a new profile has no project, so a new Windows install came up on an empty window and met the browser workspace only once a project was picked. The two startup branches that finish having restored nothing now apply the default first, before `markHandlersReady`. The rule is about the workspace rather than the platform: `shouldApplyOnFreshStart` declines any workspace that needs a project, because `{projectPath}` silently falls back to the user's home directory and applying a terminal-first default with no project would open a terminal running `claude --dangerously-skip-permissions` in `~` on first launch (#158)
- **workspace**: the settings load lost a race to its only reader. `WorkspaceSettingsManager` loaded asynchronously from `init` while the object initialises on first access - which is the startup effect that immediately calls `getDefaultWorkspace()` - so the compiled-in default won over the file. Invisible while the two agreed; on Windows they no longer do, and a user who had picked "none" or another workspace would have had the browser applied over their layout on the first project selection of every session. Loaded synchronously now, exactly as `FocusModeSettingsManager` already does and for the same reason (#158)
- **focus-mode**: a chosen edge did not persist on Windows, on the one platform where that switch is the whole escape hatch. `FocusModeSettingsManager` wrote with `encodeDefaults` off, so any value equal to the class default was omitted - and `decodeWithDefaults` reads an absent key as "never chosen" and fills it from the platform default, which on Windows disagrees for exactly these fields. Switching "Left sidebar" back on wrote nothing and silently reverted on the next launch. The encoder now lives next to the decoder as `FocusModeSettings.storageJson`, because the merge semantics and `encodeDefaults` are two halves of one contract and cannot be allowed to drift (#158)
- **focus-mode**: the platform merge reverted a pre-existing preference, the same trap seen from the other end. Files written before this build omit every value equal to the class default, so an absence there means "the user's choice happened to match", not "never chosen" - resolving all absences from the platform defaults flipped `autoRevealEnabled` off for a Windows user who had deliberately switched hover-to-reveal on. The merge now covers only `PLATFORM_DEFAULTED_KEYS`, the four `hide*` keys this build introduces, which no older file can contain (#158)
- **browser**: the sanitizers were Unicode-aware where they claimed to be structural. `Char.isLowerCase()` is true for Cyrillic, Greek and Arabic-script letters, so a role or tag value like a run of non-Latin script passed as a structural token - free text in every locale but English. `sanitizeFieldName` had the matching gap in the other direction and worse: it filtered with the Unicode-aware `isLetterOrDigit()` but redacted with `\d`, which is ASCII-only in Java, so an Arabic-digit record number survived the filter *and* the redactor intact. Hosts carrying a non-ASCII character are refused upstream instead, since an internationalised name reaches a browser URL already punycoded - and there the Unicode-aware IPv4 check is the one that refuses more, so tightening it "for consistency" would have inverted its meaning. The digit-run threshold drops from five to three, since a record number baked into a form field is routinely four (#98)
- **browser**: the interaction bridge was unrate-limited on a bus it shares. `ApplicationEventBus` is a `MutableSharedFlow` with 64 slots published via a non-suspending `tryEmit`, and the bridge is the first page-controlled producer on it - the per-batch caps bound the cost of one call, not the call rate, so a page looping `emit()` could evict `AuthEvent` / `TabEvent` / `FileChangeEvent` deliveries out from under any subscriber not keeping up. The cap is process-wide rather than per-tab, because the real ceiling was 250 times the open tab count and twenty tabs is 5,000/sec, needing nothing more unusual than a site opening tabs. The limiter reserves before parsing and keeps one entry per `emit()` non-refundable, since 64 KB of valid JSON yielding zero entries costs a whole parse and otherwise advanced nothing (#98)
- **browser**: the bridge called into the browser from the page's JS thread. `authorityProvider` ran `getCurrentUrl()` inside `emit()`, which the bridge's own KDoc says must not block that thread, and `runCatching` covers a throw but not a stall. The authority is cached in a `@Volatile` written by the navigation handler now - which is what would observe an SPA route change anyway, so freshness is identical and each batch is cheaper. It is set unconditionally, including to null, so an interaction after navigating somewhere unreportable is not attributed to the previous site (#98)
- **browser**: a navigation with no reportable authority never reached the visit tracker, so the tab was never told it had left. An error page for a mistyped host, `about:blank`, `file://` or `data:` all took that path and each left the previous visit open: dwell and active time kept accruing for as long as the user sat there and were billed to the previous domain, the depth run was never broken so returning counted as one hop deeper, and the pending navigation hint relabelled the next link click TYPED. That biases both numbers this feature exists to produce, and a mistyped host is common (#98)
- **browser**: a closing tab could still emit clicks. `dispose()` closed the visit tracker, but the interaction bridge's only gate is the cached authority and the collector flushes on `pagehide` - exactly during teardown - so a close emitted `PAGE_LEFT`, `TAB_CLOSED`, then CLICKs for a tab that was gone. The later fix for it still had a race its own comment claimed to close: `closed()` emitted both events and only then nulled the authority, so a batch landing between the two statements still read a non-null authority. The two lines are swapped (#98)
- **browser**: the window id was captured at construction and went stale on a tab move, so a moved tab kept reporting its dwell, depth and tab counts against the window it left - and since a test asserts per-window attribution is load-bearing, it would have drifted silently. A cross-window move also left a visible tab accruing no active time: the visibility signal is one `DisposableEffect` per composition and a move builds one while tearing down the other in an order this code does not control, so in the compose-then-dispose order the enter no-opped and the leave cleared the counter. A tab the user was looking at then reported dwell climbing and active time flat - "left open, never read", the exact case this class exists to distinguish. Ref-counted now, so either order is correct (#98)
- **browser**: navigation types were wrong for most page views. Every tab's first navigation goes through `browser.navigation()` directly in `init`, so new tabs, restored sessions, bookmarks and deep links all fell back to LINK - "clicked through from the previous page", the one thing they are not. They report OTHER, `loadUrlAndWait` says TYPED like `loadUrl`, and a hint nobody consumed now expires rather than sitting there to relabel the user's next click (#98)
- **browser**: rage clicks fired on three different elements, and then stopped firing where they should. The sibling-index cap reduces every row past the hundredth to the same `tbody>tr`, and rage keys on path equality, so three clicks on three rows of a large table read as rage - on exactly the page type the cap exists for. Rage now needs a path that identifies one element. Separately, the detection window re-anchored on every click, so a pagination arrow clicked once every ~900ms produced CLICK, CLICK, RAGE_CLICK and then nothing at all for as long as it continued; the window is measured from the first click of the run. Reproduced under the collector harness before and after: the old shape reports 2 clicks out of 12 and one false rage, the new one reports all 12 and no rage, while a fast burst still fires (#98)
- **browser**: scroll depth was reported at most once per document, so every SPA route after the first reported none - the host re-runs the script on each main-frame navigation, which for a single-page app is the route change, and that early return now resets the per-route state. Capture-phase scroll on `window` also saw inner scrollable elements and measured them against the document, so an inner scroll could advance the page's depth (#98)
- **browser**: `registrableDomain` could be talked into the wrong site. It stripped the scheme with `substringAfter("://")`, which takes everything after the first occurrence anywhere, so a redirect URL carrying `https://` in its query reduced to the *target* domain - the exact smuggling its KDoc says cannot happen and which a test already asserted for the well-formed shape. A scheme is only a scheme at position zero. Backslash is now a path separator as Chromium treats it, so `evil.com\@good.com` no longer reduces to `good.com`, and short numeric hosts like `127.1` no longer report as sites (#98)
- **browser**: digit redaction applied to field names but not to tokens or paths, so the identifier this code refuses to emit through one field walked through another - a custom tag like `<row-4417882>` is lowercase, matches the token charset and is short, so it was emitted verbatim, as was the element path containing it. Tags, ARIA roles and path segments are as author-chosen as a `name=` attribute. Sibling ordinals are left alone, being structure (#98)
- **browser**: `sanitizeFieldName` filtered rather than refused, which turned "John Smith" into the plausible-looking field name "JohnSmith" - the one shape most likely to be a person's name was the one shape that survived, and digit redaction does nothing for alphabetic content. Refusing only on whitespace was then too narrow to mean what the KDoc said, since deleting an out-of-alphabet character welds tokens together just the same. Anything outside the alphabet is a separator now and more than one token refuses the value; `$` stays in the alphabet because ASP.NET WebForms builds every name with it (#98)
- **browser**: three collector caps equalled the host's own, which made the host's refusal unreachable and defeated the ordering the sanitizers depend on. The host *refuses* a token over 32 characters, so slicing to exactly 32 before sending meant a 34-character custom element name arrived as a valid-looking prefix, reporting a tag that does not exist and collapsing two long elements into one. Field names were cut at the host's 64, defeating the host truncating last - that ordering exists so a digit run straddling the boundary is redacted before it is cut. Both now cut wider so the host is always the one deciding, asserted against the host's constants. And `tagName` was uncapped at the source, so one element with a megabyte-long custom tag name pushed the batch past the payload limit and dropped it whole, letting a site silence its own interaction telemetry with a single hidden element (#98)
- **browser**: interactions applied one of the two gates page views apply. Chromium commits an error page as a real document, so the collector ran inside it and found an authority - clicking "Reload" after a mistyped host reported a CLICK for a domain the user never reached, while the comment beside it stated both gates as the invariant. A failed load now clears the authority rather than only skipping the page view (#98)
- **browser**: `STARTED_FLAG` was set before the listeners were wired, so a throw in between was swallowed by the outer catch and left the flag standing with no listeners and no reset function - the collector dead for that document, with every later re-injection taking the "already collecting" path and no signal anywhere. Claimed last now, so a failed injection is retryable on the next navigation (#98)
- **browser**: a tab on an unreportable host reported as `about:blank`, indistinguishable from an empty tab, so "new tabs opened" read high by however much someone used a dev server. `TAB_CLOSED` had the same conflation from the other end and left opens and closes unbalanced per sentinel. Separate sentinel, at both ends, no privacy cost. Nearly every tab's first `TAB_ACTIVATED` also said `about:blank`, since the open and the initial load run in `init` before any `NavigationFinished`; it falls back to what the tab was opened with (#98)
- **browser**: the collector read `el.name` off every element. It is a real IDL attribute on `img`, `a`, `iframe`, `object`, `param`, `meta` and `map`, and on a custom element it is whatever getter the page defined - so off anything but a form control it is author-controlled free text, which is exactly what the field-name sanitizer assumes it is not. Same tag restriction `el.type` already had (#98)
- **browser**: two rate-limiter refunds could credit a window they never took from. The process-wide `giveBack` asked whether the current window was fresh, true of every window in its first interval including one that just rolled, and the per-tab side tracked its reservation in one field every reserve overwrote, so two overlapping `emit()` calls could cross-credit. Both carry a token now and refund independently against their own stamps, rather than resting on JxBrowser never delivering two batches at once (#98)
- **browser**: `emit()` caught bare `Throwable`, so an `OutOfMemoryError` was swallowed by a telemetry boundary; `LinkageError` and `Exception` are enumerated now, matching `deliverContextMenu`. It is also no longer silent, logging the exception class - never its message - at most once per rate window, so a wiring break stops looking identical to a page nobody touched (#98)

## Improvements

- **browser**: `pathOf` counted a sibling index by walking `previousElementSibling` to the start, at five levels, synchronously in a capture-phase handler ahead of the page's own - clicking a cell in a 10,000-row table was about 10,000 property reads, and `focusin` paid it again per field, with large tables being the normal case in the deployments this targets. Capped at 100 and verified under a fake DOM: 10,000 reads down to 101. The same run showed paths vanishing on component frameworks, since five levels of a long custom element name exceeds the host's limit and the host refuses rather than truncates, so `elementPath` went silently absent on exactly the enterprise apps this targets; `pathOf` spends a budget now, dropping outer levels first, so depth degrades instead of the field disappearing (#98)
- **browser**: the scroll handler stops reading `scrollHeight` once the page is fully scrolled, which was a forced layout per event on the virtualised lists this targets, and a one-pixel epsilon makes 100% reachable at fractional DPI. `RAGE_CLICK.repeatCount` was always exactly the threshold, since the event fired at three and every later click returned early - three frustrated clicks and thirty were indistinguishable - so later clicks in the burst update the queued event in place (#98)
- **browser**: an executable test for the collector, wired into CI. `scripts/test/test-browser-collector.js` extracts the real script out of the Kotlin string and runs it against a fake DOM, which also closes a coupling the Kotlin tests cannot see: the collector's path limit and the host's are hand-matched across two files and two languages, and the host refuses an over-long path rather than truncating, so drift makes `elementPath` vanish silently. Mutation-checked rather than assumed green - removing the sibling cap, the path budget, the form-control restriction on `name`, the per-route reset and the rage truncation guard each fail it, and two mutations that initially survived exposed a bound reading the same constant it was testing (#98)
- **browser**: `BrowserAnalyticsEmissionTest` captures real events off the bus rather than re-implementing the predicates it checks. The kill switch - a `val` read at class init - had no test and could not have one, and the bounds checks passed whether or not the emitter still applied them; the resolution rule is extracted as `telemetryEnabledFrom(env, property)` and tested, which is how the truthy vocabulary, the property fallback and an empty env var shadowing the property were all uncovered (#98)
- **docs**: the kill switch has an operator-facing entry in `AGENTS.md`, along with two properties of the data that were better stated than implied - `PluginContext.applicationEventBus` is ungated, so these events are readable by every installed plugin rather than only the analytics plugin that owns egress consent, and the interaction numbers are attacker-influenceable by design, since a page can fabricate its own engagement within the rate cap or suppress it by pre-setting the started flag (#98)
- **workspace**: predefined panel ids come from a counter rather than `currentTimeMillis()` plus a 1-in-10000 random draw - the whole list is built in one initializer, so a collision was a dice roll on each launch and panel ids key the split tree. "Browser Only" is named that rather than "Browser" because `WorkspaceManager` identifies predefined workspaces by name, so a built-in called "Browser" would silently swallow a user's own saved layout of that name; names are now covered by a uniqueness test alongside ids, and the workspace is appended to the picker rather than prepended, since one platform's default is not a reason to reshuffle what everyone else sees (#158)
- **settings**: both settings singletons are warmed off the UI thread from `main.kt`. They load synchronously in `init` on purpose, but their first accessor would otherwise be a composition-thread effect, putting `mkdirs`, a read and - on the first launch after an upgrade - a migration write on the UI thread. This narrows rather than eliminates it and is correct either way, since JVM class init is locked (#158)
- **focus-mode**: the per-edge switches are no longer disabled while focus mode is off. You had to turn it on, losing the top bar, before you could choose what it clears; `hides()` gates on `enabled` anyway (#158)
- **tests**: `ProjectPanelOpenerTest` fails if a direct `PanelEventBus.openPanel` reappears in the startup effects, since those effects only run inside a composed window and a fourth call site would reopen the panels on Windows with no behavioural test able to see it. `FreshStartWorkspaceTest` pins the project-placeholder list against the substitution it mirrors, because a fifth placeholder added there and missed here would stop marking a workspace as project-requiring and the failure mode is a CLI running in the user's home directory (#158)

## Dependencies

- **boss-plugin-api** 1.0.74 to 1.0.76, for the browser telemetry event types (`BrowserEvent`'s navigation and engagement fields, `BrowserInteractionEvent`, `BrowserNavigationType`, `BrowserInteractionType`). Verified against the release jar as a superset rather than assumed from the ordering: 1.0.76 carries the `AiGatewayAPI` and `BrokeredCredentialProvider` that 1.0.74 was pinned for, plus `AiAvailability` / `AiReadiness` and `LlmApiFormat.OPENAI_RESPONSES`. `fetchApiPluginJar` has no Maven fallback, so a pin that dropped a type would surface as an unrelated compile error (#98)
