# BOSS v9.4.8

**Release Date:** 2026-08-11

Two reachability fixes and a repo boundary. Focus mode no longer strands Settings, Search and Sign Out behind a hidden top bar, a plugin tab type that asks for no input opens on the first click instead of showing an empty optional field, and the RISA LLM gateway service moves to its own private repository.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **Settings, Search and Sign Out stay reachable in focus mode.** Those three actions live in `BossTopRightBar` and nowhere else, so clearing the top bar takes them with it. The documented way back - hovering the top edge - is driven by Compose pointer events on an edge strip and cannot fire over a browser tab, because in `HARDWARE_ACCELERATED` mode Chromium owns a foreign native window that composites over the Compose scene. That is why auto-reveal is off by default on Windows, and it left focus mode plus a browser tab with no route to these actions except the menu bar. An icon-only cluster now pins to the bottom-right of the content area, composed only while the top bar is hidden (#161)
- **No-input plugin tab types open on click.** A plugin whose `NewTabSpec` declares no input showed a pointless "(optional)" field and a confirm button before it would open. Arcade is the only such type today; any future one gets instant open for free, and types declaring real input keep the select-then-type flow (#167)
- **The LLM gateway service leaves this repository.** It is a Python FastAPI service on Cloud Run that ships in no BOSS release, is referenced by nothing in the Gradle build or CI, and deploys on its own pipeline - yet this repo is public, so every infra and authorization change to it was a public change reviewed by app reviewers. It now lives in `risa-labs-inc/risa-llm-gateway` (private), imported with `git subtree split` so authorship and history came across. What stays is the app's half of the contract, now written down in `docs/llm-gateway-contract.md` (#168)

## Features

- **tabs**: the new-tab dialog opens a no-input plugin type the moment its tile is clicked. `needsNoInput` is a heuristic over three `NewTabSpec` fields rather than a declared flag, so it is `internal` with a truth table behind it: the api defaults were read from the pinned boss-plugin-api 1.0.76 jar (`inputLabel` defaults to "Input", `inputOptional` to false), which means instant open cannot be reached by omission - opting in takes setting all three deliberately. An explicit `opensImmediately` flag would replace the heuristic but needs an api release, so it waits for the next one (#167)
- **panel**: a focus-mode quick-action cluster rendering through `OverlayCorner`, for the same reason the hover strip cannot be reached - a plain Compose overlay draws behind the browser surface, which would leave the feature working everywhere except where it is needed. Two guards come with that, both from `ToastOverlay`: nothing is composed while the top bar shows, and an unfocused window draws in place rather than holding a dead click region over whatever the user switched to. The sign-out hint carries the signed-in address, as the top bar prints it next to the same button (#161)

## Bug Fixes

- **tabs**: a refused instant-open was a complete no-op. `openPluginTab` returned Unit and treated null from `createTabInfo` as "input rejected, dialog stays open" - a contract that only makes sense when there is input on screen to correct. On the tile path there is none and the tile does not even become selected, so a plugin that throws rendered a button that visibly did nothing, forever. It now reports whether it opened and falls back to selecting the type, which degrades to the old behaviour. A create already in flight is deliberately kept distinct from a refusal, so the second half of a double-click does not rearrange the dialog on its way out (#167)
- **tabs**: the auto-select path bypassed the change entirely, and the first fix for it was worse than the bug. When no built-in types are registered the dialog preselects the first plugin type, so a no-input type sorting first opened showing exactly the UI this change removes. Gating the head of an if/else-if chain that ends in an unconditional `else` did not render nothing - it fell through to the URL field, putting a focused "Enter URL or search term" next to a "Play" button that discards what is typed. The no-input case is now a branch inside the plugin branch, so selecting a plugin type can never leak into the built-ins (#167)
- **tabs**: double-clicking a tile opened two tabs. `onCreateTabInfo` and `onDismiss` are state-driven, so a second click landing before the dialog leaves composition created a second tab. The confirm button always had this; a tile is a far more natural thing to double-click (#167)
- **panel**: the overlay corner tracked the window's bounds on the frame clock. A `withFrameNanos` loop registers a frame awaiter, so the Compose scene never went idle - a full repaint plus a native `locationOnScreen` every frame, for a rectangle that only changes when the user moves or resizes the window (#161)
- **panel**: the inset was read above the branch that uses it, so the lightweight path subscribed to `contentInset` and recomposed on every frame of a 250ms sidebar animation - the exact cost the lambda parameter exists to avoid. The pre-measurement bound also comes down to 100x34: with no `remember` key it resets on every refocus, so a window created at 120x40 and positioned for that size snapped to its real ~94x30 on every alt-tab back into BOSS (#161)
- **logging**: five `[HOST-DEBUG]` printlns on the navigation-target path - four in `NavigationTargetProviderImpl`, one in `SandboxedPluginContext` - went to stdout unconditionally on every navigation event, with no category or level to filter by. They now log through `BossLogger` under `LogCategory.EDITOR` at debug, with path, line and column as structured data rather than one interpolated string. Two detekt baseline entries suppressing `MaxLineLength` for the deleted lines retire with them; detekt does not fail on unmatched entries, so CI had nothing to say about the stale one (#160)

## Improvements

- **panel**: `OverlayCorner` gains an optional inset. The lightweight path aligns inside the caller's `BoxScope`, but the heavyweight one places a window against the whole content pane, so `BottomEnd` alone lands on top of the status bar and the right sidebar - both of which the Windows focus-mode defaults leave visible. The inset shrinks the rectangle the corner resolves inside, moving the window without enlarging it, so the region whose clicks it swallows is unchanged. Existing callers pass zero and are unaffected (#161)
- **panel**: `onSignOut` becomes required on both `BossTopBar` and `BossTopRightBar`. It used to open the confirmation itself, so moving that into `BossAppDialogs` turned Sign Out into a button that renders, hovers, shows its hint and does nothing if the argument is dropped. One line at the single call site converts that into a compile error (#161)
- **tests**: the highest-consequence line in the focus-mode cluster had no test behind it. The scaffold passed `hides(TOP) && !showTopBar`, where the first conjunct looks redundant and is actually what keeps the cluster off the launch path, since `showTopBar` is written from a `LaunchedEffect` and reads false on every window's first composition. Dropping it means a native always-on-top window created and disposed on every window open, for users who never enable focus mode. It is now a named pure predicate with four cases, mutation-checked. `ContentInsetLayoutTest` measures a scaffold-shaped tree rather than the formula, and had to run at 2x density because at density 1 every wrong answer equals the right one (#161)
- **docs**: `docs/llm-gateway-contract.md` records the endpoint, the auth header, the three response fields the client parses, and who owns changing what. Nothing links the two repositories at compile time or in CI any more, so this is all that stands between them and silent drift. A v9.4.5 release note claiming clients "now get a message this gateway owns" is corrected in the same pass - that was gateway-side code which was never deployed (#168)

## Dependencies

- **kotlin**: 2.4.0 → 2.4.10, covering the multiplatform, jvm, compose and serialization plugins plus `kotlin-test-junit` (#166)
- **ktor**: 3.5.1 → 3.5.2 (#162)
- **androidx-lifecycle**: 2.10.0 → 2.11.0 (#163)
- **netty**: 4.2.16.Final → 4.2.17.Final for `netty-transport-native-epoll`, `-kqueue` and `-unix-common`. All three moved in one commit because they share a pinned version string, so the second dependabot PR landed as an empty diff (#164, #165)
