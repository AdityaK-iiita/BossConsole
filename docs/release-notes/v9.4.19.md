# BOSS v9.4.19

**Release Date:** 2026-08-19

A small release with one change: Auto Save is a checkable item in the File menu, reading and writing the editor-tab plugin's own setting rather than keeping a second copy of it in the host.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **Auto Save is in the File menu, where the rest of the save actions already are.** The setting itself stays with the editor, which owns the save path, the modified flag and the debounce; the host only draws the control, and only because plugins cannot contribute to the native menu bar - which is the entire reason this needs host code at all (#212)
- **The item is hidden rather than shown dead.** `rememberAutoSaveEnabled()` returns null when there is no editor-tab plugin installed, or when the installed one predates the setting. An unchecked box in that case would be indistinguishable from auto save being off and would do nothing when clicked, so nothing is drawn (#212)

## Features

- **editor**: a checked `Auto Save` toggle under File, wired through `EditorTabPluginAPI` by `EditorAPIAccess.rememberAutoSaveEnabled()` / `setAutoSaveEnabled()`. The read is Compose-observable through `rememberProvider()`, so the checkbox picks the plugin up when its asynchronous startup registration finishes instead of staying hidden until the next launch, and it follows a change made anywhere else in the editor (#212)

## Improvements

- **editor**: `EditorAPIAccess` follows `TerminalAPIAccess` rather than introducing a second shape for the same host-to-plugin bridge, and `setAutoSaveEnabled` resolves the provider per call, so it is a no-op when the plugin is absent instead of holding a handle that may not exist yet (#212)
- **quality**: `rememberAutoSaveEnabled` collapses its two early returns into a null-safe chain - shorter than the guard version, and inside detekt's `ReturnCount` limit of two (#212)

## Dependencies

- **boss-plugin-api**: 1.0.79 → 1.0.80, for the `autoSaveEnabled()` / `setAutoSaveEnabled()` pair on `EditorTabPluginAPI` (#212)

## Known Limitations

- **There is no keyboard shortcut for the toggle.** Auto Save is reachable only through the File menu (#212)
- **A host older than the editor plugin shows nothing.** The gate answers "hide" for both an absent plugin and one too old to answer, so a user on a build without the api pin sees no item and no explanation of why - the setting is still reachable from the editor's own settings panel (#212)
