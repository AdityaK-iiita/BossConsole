# BOSS v9.2.61

**Release Date:** 2026-07-28

Security-and-correctness release across the external surfaces: the passkey edge function now actually verifies what it signs, the `boss://` and single-instance entry points authenticate and attribute their callers, and the closing-plugin-classloader `LinkageError` that crashed the app on terminal-tab hot reload is fixed. On the feature side, plugin UI over IPC works in both directions for the first time, and a new **Help ▸ Import Passwords & Bookmarks…** dialog reads installed browsers or their exports into the encrypted vault.

## Highlights

- **Passkeys are verified server-side**: the edge function compared only the caller-supplied challenge copy and never the challenge inside the signed `clientDataJSON`, never checked `authData.rpIdHash`, and never stored a signature counter. Verification now covers the signed challenge (with the storage lookup keyed on it), RP-ID hash pinning, a monotonic counter with compare-and-set, ES256 **and** RS256, and base64/base64url in either alphabet - plus unconditional single-use challenge consumption, an authenticated `/register/challenge` so a caller can no longer mint a challenge for someone else's account, and authenticated `/manage/*` so an anon key plus a user id can no longer enumerate or delete an account's passkeys (#46, #56).
- **Import passwords and bookmarks**: reads Chromium-family logins straight out of `Login Data` using the key from the OS keychain (macOS PBKDF2-SHA1/1003 + AES-128-CBC, Linux via the documented fallback), Safari and Firefox bookmarks natively, and falls back to RFC 4180 CSV / Netscape bookmark HTML where a browser can't be read. Scanning never decrypts, so opening the dialog can't trigger a keychain prompt; counts and reasons are logged, never a credential (#67).
- **Plugin UI over IPC works both ways**: the host was dialling *out* to the plugin's `PluginUIService`, repacking every outgoing `UIEvent` as a `WidgetUpdate` that carried only `surface_id` - so no click, typed value or dropdown index ever reached an out-of-process plugin, and no plugin-pushed tree reached the host. A new `PluginUIServiceBridge` plus a `RemoteUiSurfaceRegistry` rendezvous supplies the missing server half, and key, scroll and lifecycle events now have emitters (#48, #50, #51).
- **The external entry points state who asked**: `boss://` links carry a `DeepLinkOrigin`, so a `terminal?command=` from BOSS's own CLI runs as before while anything else is shown to the operator for confirmation first. The single-instance descriptor moves out of the shared system temp directory into `~/.boss/run` with a startup-minted token and a Unix-domain socket on macOS/Linux, and log sanitizing now masks a credential that reaches a message with no URL around it (#60).

## Features

- **security**: **Help ▸ Import Passwords & Bookmarks…** - native import from Chrome/Edge/Brave/Vivaldi/Opera/Arc, Safari and Firefox, plus CSV and Netscape-HTML file import for everything native can't reach, with a preview step before anything is written. SQLite reads work on a 0700 temp copy including the `-wal`/`-shm` sidecars, bookmarks go in via `addBookmarks` (api 1.0.69) with a reflective fallback for older plugins, undecryptable and unreadable stores are reported rather than shown as "no saved passwords", and `ImportedPassword.toString` is redacted so one interpolated row can't defeat the logging discipline (#67)
- **remote-ui**: invert the `PluginUIService` transport so the plugin is the gRPC client and the kernel the server - `PluginUIServiceBridge` implements `RegisterUI`/`StreamUI`/`UnregisterUI`, and `RemoteUiSurfaceRegistry`/`RemoteUiSurface` let the plugin and host halves start, stop and restart in any order (a tree arriving with nobody attached is retained; a component attaching to a live surface is replayed). Per-surface outgoing queues are bounded at 256 and shed the *oldest* event so `TextChange` last-write-wins isn't inverted, and a dying stream releases its registration so a crashed plugin isn't locked out of its own respawn (#50)
- **remote-ui**: emit the three event families #34 deferred - `key` (a Compose tap downstream of `AWTKeyboardInterceptor` that re-checks the live keymap and always returns `false`, so a plugin can observe leftovers but never trap the user), `scroll` (coalesced to ~60ms via `ScrollCoalescer`, whose emitted deltas sum to the total displacement), and `lifecycle` (`created`/`destroyed` as a matched pair guarded by a CAS latch) (#51)

## Bug Fixes

- **passkey**: verify the signed challenge, `rpIdHash` and signature counter server-side, hash `clientDataJSON` as raw bytes, decode every payload through `decodeBase64Any`, and verify User Present on both ceremonies; challenge consumption is unconditional and atomic so a captured assertion can't replay on the direct path, `/register/challenge` and `/manage/*` require a verified caller, `rpId` has one source of truth and must correspond to the ceremony origin, loopback RP IDs and origins are gated on an explicit dev signal, and the completion row is written once with its session already minted so a cross-device poll can't strand an unclaimed token pair. Migrations `20260725000000`–`20260727000000` add `public_key_alg`/`sign_count`/`rp_id` and a partial unique index on `session_id`; a new `edge-functions.yml` job runs `deno check` + `deno test` on PRs touching the function or its migrations - nothing ran them before. 146 tests passing, was 62 passing / 6 failing (#46, fixes #35)
- **passkey**: revoke `create_mobile_registration_session` from `PUBLIC`, not just from `anon`/`authenticated` - Postgres grants `EXECUTE` to `PUBLIC` at creation and both roles inherit it, so the earlier revoke left this `SECURITY DEFINER` function (which mints a registration challenge bound to any account it can find by email) reachable with the anon key. Verified against production: the same request now returns `42501` instead of the function's own error (#56)
- **plugins**: stop a closing plugin classloader from resolving plugin classes against the host - a closed `URLClassLoader` answers `findClass()` with `ClassNotFoundException` for *every* name including the ones its own jar carries, and `loadClassChildFirst` read that as "the plugin doesn't have it" and delegated to the parent, splicing two class graphs into the `LinkageError` that crashed terminal-tab hot reload. Post-`ACTIVE` first-time loads are now refused with a `ClassNotFoundException` naming the plugin, class and loader state, logged once per name at WARN; already-defined classes, shared parent-first packages and the plugin's still-open jar are untouched (#57)
- **deeplink/single-instance**: decide `boss://terminal` commands by where the request came from - every producer states a `DeepLinkOrigin`, the origin travels with a command queued across a cold start, and only `OPERATOR_CLI` runs unprompted (a command too long to display in full is dropped rather than prompted, since nobody can approve what they can't see). The single-instance lock file - previously a pid and a port in the shared system temp directory, acted on by the server for any line it received - becomes a token-authenticated, owner-only descriptor in `~/.boss/run` over a Unix-domain socket (loopback TCP on Windows), "another instance is running" now means something answered on the channel, and a crashed instance's descriptor is reclaimed instead of blocking startup (#60)
- **logging**: mask credentials that reach a message with no URL around them - `sanitizeExceptionMessage`/`sanitizeStackTrace` applied only the path/URL/email rules, so `token=ghp_…` or `SUPABASE_ANON_KEY=eyJ…` in a config-parse error survived verbatim. Two passes are appended: a structural `credentialShapePattern` (JWT, `gh[pousr]_`/`github_pat_`, `sk_`/`pk_`) with boundaries that leave `task_manager_configuration` alone, and a `name=value` pass that masks the value but keeps the name - except for `null`/`true`/`false`, where "token=null" *is* the diagnosis (#60)
- **browser**: only record history for pages that actually loaded - a typo like `youtube.como` commits a Chromium error page that fires `TitleChanged` and "load finished" like any other navigation, so it was saved as a visited page and came back as a suggestion forever. A `NavigationOutcomeTracker` publishes each finished main-frame navigation's outcome before listeners run, keyed on a canonicalized URL; HTTP errors from a real host still count as visits, and the destructive path is fenced hard - eviction requires that some page with a real host loaded in the last 60s (so a DNS outage or captive portal can't read as every site ceasing to exist), a `ResolvedHostsStore` means a host that has *ever* served a page is never evicted wholesale, and race retraction only takes single-visit entries recorded for an error page (#66)
- **browser**: fix suggestion ranking and in-session duplicates - `suggestableHost` kept `www.` and dropped the port while `canonicalUrlKey` did the opposite, so typing "you" never matched `www.youtube.com` and `localhost:3000`/`localhost:8080` were one domain; both now share `normalizeAuthority` and `loadHistory` recomputes the domain to repair files written earlier. Ranking was recency wearing a visit-count label (`visitCount * 1000 + lastVisited / 1_000_000` puts the recency term near 1.75e6, so ~1750 visits were needed before the count moved anything) and is now a bounded 0..100 recency decay breaking ties between visit counts. History is keyed by page identity as it is recorded, and both stores bind a save's destination and contents when the write is *requested* - resolving them inside the coroutine let a test's background save write an empty history over the developer's real one (#70, closes most of #69)
- **updater**: give the updater one owner - every window's `onDispose` called `UpdateManager.cleanup()`, so the first window to close cancelled the shared scope and killed periodic checks plus any in-flight download for every window still open, with nothing able to re-create it. `UpdateCoordinator` now owns `UpdateManager` and is the only thing that can `shutdown()` (from the JVM shutdown hook); windows hold an `UpdateHandle` with no teardown entry point at all. "Last Session" is written by exactly one dispose gated on the last window closing, synchronously - so closing a secondary window no longer overwrites the primary's layout. Also: helper scripts resolve through the platform temp directory instead of a hardcoded `/tmp/boss-updater`, `validateDownloadFile` fails closed and shares `UpdatePathValidator` with the script generator, and helper scripts are 0700 (#47, fixes #37, fixes #19)
- **deeplink/downloads**: resolve the target window once at dispatch through `resolveActionableWindowId()` - handlers read `focusedWindowFlow` directly, so an MCP- or CLI-driven caller holding OS focus itself got `boss://folder`, `boss://plugin` and `boss://terminal` dropped with a warning while `boss://split` worked from the same caller. Host routing also matched with `startsWith` (so a future `boss://filesystem` would have been mis-parsed as `boss://file`) and now matches the whole host, `boss://folder` validates its path on `Dispatchers.IO` behind the same `CLISecurityValidator` check as the CLI, and `removeDownload` cancels an unfinished download in the engine and cleans up the partial file instead of leaving JxBrowser writing bytes nothing tracked (#44)
- **remote-ui**: repair the `boss-ui-sdk` ⇄ `RemoteWidgetRenderer` contract - eight defects surfaced by porting the renderer to Rust. `WidgetTreeBuilder.button()` wrote `onClickEvent` while the renderer read `clickEventId` (every builder-built button clicked with an empty id), `sendUIEvent()` had no `"selection"` branch so dropdown picks arrived with an unset oneof (now a total function over a sealed `WidgetEvent` via `UIEventMapper`, so a missing case is a compile error), builder ids are deterministic `w0, w1, …` instead of per-build UUIDs (random ids made every update a remove-all/add-all that discarded what the user was typing), `WidgetDiffEngine.apply()` links a child idempotently, `LIST` renders its comma-joined `items` when it carries no child nodes, `alpha` is honoured with proto3's presence gap resolved as a documented sentinel, and `background_color` resolves all 17 theme tokens against the live theme. No proto structural change, so the IPC wire version stays 1.0.0 (#48)
- **packaging**: raise the macOS floor to a real one - `LSMinimumSystemVersion` was 10.15 while the downloaded browser-engine bundle declares 12.0, so on 10.15/11 the app installed, launched, and died in dyld the first time an engine loaded. `xdg-utils` moves from the generated `.deb`'s `Depends` to `Recommends` so `dpkg -i` on a headless image reaches `postinst` and its existing `xdg-*` guard; `CFBundleVersion` becomes a monotonic build id so a re-notarized rebuild is distinguishable; `LSApplicationCategoryType` replaces jpackage's "Unknown"; the Info.plist keys that were declared twice are single-sourced; Windows gains `BOSS.exe --unregister-protocol` so an uninstall can drop the runtime-created `boss:` handler; and the inert `cs.debugger`/`device.serial` entitlements are dropped (#45, #49)
- **orchestrator**: confine manifest source reads, keep snapshots on reset, and report approvals honestly - `ProcessManifest.sourceFiles` arrives over the socket from the process being diagnosed and its contents are posted to a model, so a new `AllowedRoots` resolves each candidate by path component against a root that must now be stated explicitly (`projectRoot` defaults to null, meaning no source file is read at all). `RESET_STATE` no longer deletes every snapshot at the third failure with no approval - it names the newest one and reports which snapshot the process comes back on. `approveRepair` reports what actually happened instead of always answering `applied = true`, and an approved repair acts on the process rather than asking the kernel to shut down a repair UUID. `CancellationException` is rethrown at all four suspend-callback catches rather than being reported as a repair failure (#68)
- **git/shell**: ignored porcelain entries are not staged - `parseStatusLine` carved only `UNTRACKED` out of `isStaged`, so an `!!` entry came back `isStaged = true`, and fixing that boolean alone would have left it rendering under "unstaged changes" one column over. Both status call sites now go through `parseStatusOutput()`, which drops `IGNORED` wholesale, while `parseStatusLine` stays faithful to porcelain. `escapeForDoubleQuotes` gains an internal `isWindows` overload so both branches are driven on every host - the PowerShell branch was previously covered only by the `windows-latest` matrix leg (#42)
- **release**: resume a dropped notarization poll instead of failing the build - run 30067806575 lost release 9.2.59 to a network blip (`statusCode: nil`, i.e. no HTTP response at all), which single-shot `notarytool submit --wait` read as a failed notarization. The retry now *resumes* via `notarytool wait <id>` rather than re-submitting, with the submission id latched only once Apple confirms a completed upload and only if it matches a UUID shape, a probed per-attempt `--timeout`, exponential backoff, a total budget so the macOS bill stays bounded, and fast-fail on a real verdict or a credential error. Extracted to `scripts/lib/notarize-dmg.sh` with 20 assertions in the existing Shell Script Tests job, and shared with `release-lite.yml` (#41)

## Improvements

- **kernel**: make `ContextMenuServiceBridge` honest - it claimed to render plugin context menus through the host's native menu system and forward action callbacks, but stored registrations in two `ConcurrentHashMap`s nothing read. The write-only maps and accessors are gone, each RPC acknowledges and logs at debug so the passivity is structural, and the KDoc plus `context_menu.proto` state what wiring it for real would require. Registration is now unconditional rather than gated on a `contextMenuProvider` the bridge could never delegate to (#43, fixes #30)
- **build**: drop the accidental ktor **server** stack from the host - `ktor-server-cio`/`-core` arrived only via supabase `auth-kt`, whose sole consumer is a localhost OAuth callback BOSS never uses, and no host source outside the standalone `server/` module imports `io.ktor.server.*`. That removes the 529 classes the hot-reload `LinkageError` was drawn from, and `KtorServerAbsentFromHostTest` scans the classpath for `io/ktor/server/` (naming the jar) so a future supabase bump fails in CI rather than in a packaged build (#57)
