# BOSS v9.4.23

**Release Date:** 2026-08-21

Four changes: a browser handle whose transport had died could freeze the whole app through the log path, the browser gains a plugin-facing page event channel and stops two script injectors clobbering each other, an approved organisation's admins can now publish plugins for their own organisation, and an alert's scrollbar is measured in the viewport rather than in the content it scrolls.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **A dead browser tab could take the window with it.** Two independent defects, and it took both. A handle whose Chromium transport died stayed `isValid` forever, so it was never pruned and every sync call through it threw - which aborted `findBrowserForTab`'s scan at the first zombie and left the lookup permanently broken, retried every ~1.5s by a polling plugin. The freeze itself was the log path: each captured line rebuilt the whole log model synchronously from inside `PrintStream.write`, holding the `System.out` monitor, so a repeating stack trace had the app allocating hundreds of thousands of objects a second (6411 GCs, 59s of GC time) and serialising every logging thread - the UI thread included - against a queue full of its own output (#223)
- **A page event channel for plugins.** `BrowserHandle.setPageEventScript` evaluates a plugin-supplied script at document start and forwards what it emits, without parsing the payload - fluck-browser's "save this password?" prompt needs the credential at the moment of submit, before the navigation that destroys the JS context, and it owns every rule about what is worth reporting (#222)
- **Starting a tab share silently broke Cmd+F for that tab.** JxBrowser allows exactly one `InjectJsCallback` per browser and a second `set()` replaces the first without a word, which is why `BrowserInjectDispatcher` exists - and co-browse capture called `browser.set` directly anyway, evicting the find-chord probe for the rest of that tab's life (#222)
- **An approved organisation could not publish anything.** Its admin role is seeded with `organisation.admin` + `organisation.read`, publishing needed the global `plugins.create`, and there was no path from one to the other - so every new organisation waited on a platform admin (#221)

## Features

- **browser**: `setPageEventScript(script, callback)` arms the channel and `clearPageEventScript()` disarms it, matching `startCoBrowseCapture`/`stopCoBrowseCapture` on the same interface. The callback takes `(url, json)`, with the URL read from `lastCommittedMainFrameUrl` at emit time so it names the document that actually posted rather than whatever the tab moved on to; the first consumer uses it to decide which site a password gets stored against (#222)
- **browser**: `supportsPageEventScript()` returns true here. Silence had three causes a consumer could not separate - no implementation, a host-side size or rate drop, and the user doing nothing (#222)
- **browser**: Settings > Browser > Secret Manager gains "Suggest Strong Passwords" and "Offer to Save Passwords", both on by default and mirrored to system properties, since the plugin loads in a classloader that cannot see `BrowserSettings`. The defaults are published from the init block - a property initializer does not run through its own setter, so a first launch would otherwise leave them unset, and an absent property reads as "off" in the obvious check (#222)
- **plugin-store**: there are now two ways to be allowed to publish, in `services/publish-authz.ts` - `plugins.create` (or global admin), unrestricted and behaviourally identical to the gate it replaces, and an organisation whose own `publish_policy` / `publish_role_id` admits you. The default policy is `admins`, so a founder qualifies the day the organisation is approved (#221)
- **plugin-store**: an org-scoped publish of a new plugin records `visibility = 'org'` rather than taking the column default, so an organisation's own plugin lands on its own shelf; reaching the global store is a second, deliberate act through `set_plugin_visibility` (#221)

## Bug Fixes

- **browser**: `BrowserHandleImpl` latches `connectionDead` when a sync call fails on a gone transport, so `isValid` goes false and the existing prune finally collects the handle. `isValid` was `!disposed && generation matches && !browser.isClosed`, and `isClosed` only reports what this side has been *told* - it covers a browser outliving its engine but not this browser's connection closing while the generation still matches (#223)
- **browser**: the sync accessors report failure by value instead of throwing, at debug rather than WARN-with-stack-trace, and `isSecure`, `goBack`/`goForward`/`reload`/`stop` and the four zoom mutators are routed through the same path. That also makes the latch reliable - it is only set inside `syncCall`, so before this a dead handle first reached through `reload()` threw and was never marked dead (#223)
- **browser**: pruning goes through the same dispose path window teardown uses, wrapped per handle. Removing the map entry alone left two executors, three scopes and every JxBrowser subscription behind - and since `disposeAllForWindow` resolves handles through those maps, an unregistered handle could never be reached by teardown either, making the leak permanent rather than untidy (#223)
- **browser**: "Failed to receive the response." is not treated as terminal. It describes a round trip that did not come back, which is also what a live-but-wedged renderer produces, and latching on it would silently refuse every navigation and zoom call on a tab that renders fine. Nothing is lost: the cause chain is matched, and the observed failures carried "The connection has been closed." (#223)
- **logging**: `LogDataProviderImpl` coalesces rebuilds onto its own scope with a floor between them, keeping the log listener O(1) and off the writer's thread, and `DesktopLogCapture` tracks its own length instead of calling `ConcurrentLinkedQueue.size()`, which is O(n) by contract, once per line and again per iteration of its own trim loop (#223)
- **logging**: the setters request a rebuild instead of performing one, so the single consumer owns every write to `_logs` and a background rebuild cannot land after a filter change and repaint the previous filter's contents. The consumer loop also catches its own failures - an exception would have ended it and stopped the panel updating for the session (#223)
- **browser**: co-browse capture registers through `BrowserInjectDispatcher`, and `dispose()` no longer removes the shared slot, which would have taken it from every other injector (#222)
- **browser**: three defects in `BrowserInjectDispatcher`. `dispose()` claimed nothing leaked because the registry keys weakly - but a `WeakHashMap` value strongly references what it captures, and these injectors are lambdas closing over their handle, so each entry pinned a whole `BrowserHandleImpl` per closed tab; `register()` inserted its entry before `browser.set`, so a throwing set left the entry behind and every later register hit the early return, leaving every injector on that browser inert for its lifetime, silently; and `register()` now returns a Boolean so a caller does not latch a flag on a failed first attempt (#222)
- **browser**: unregistration also happens from `BrowserClosed`. `dispose()` returns on its first line once `disposed` is set, so for a browser that closed on its own - crashed renderer, engine recycle - the entry pinned its handle for the session, which is the leak the unregister was added to fix arriving through the one path that skipped it (#222)
- **plugin-store**: `plugins.create` is decided before the resolver's refusal, so an organisation's publish policy cannot veto a global publisher. Diagnosed live on a fluck-agent release that 403'd: the release key is bound to `@boss`, whose policy is `admins`, and its owner holds `plugins.create` but is not a boss org admin. Nothing caught it because only a *new* plugin id resolves an organisation at all, so the whole fleet kept publishing while the create path was broken for every first-ever publish (#221)
- **ui**: an alert body's scrollbar is measured in viewport space. It was a sibling of the content *inside* the scrolled box, and `verticalScroll` measures its child against an infinite height - so a `matchParentSize` scrollbar came out about 996dp for a 40-line body against a ~150dp viewport and translated upward out of view as the user scrolled (#219)

## Improvements

- **browser**: resolving a plugin's browser tab costs no IPC. `findBrowserForTab`'s fallback scanned every active handle calling `getCurrentUrl()`, a blocking round trip into Chromium, on a path panels poll every second or two. Handles now carry `lastKnownUrl`, seeded from the creation config and updated in the same `NavigationFinished` main-frame branch the plugin's own tab state gets its URL from - so both sides of the comparison come from one event rather than a tracked value against a live read (#223)
- **browser**: matching is via `isAtUrl` rather than an exposed getter, deliberately - a caller holding the string would be tempted to fall back to a live read when it looked stale, which is the round trip this removes. No `.getCurrentUrl()` call on a handle remains anywhere in `desktopMain` (#223)
- **logging**: `LogDataProviderImpl` is per window, not process-wide, and its consumer was never cancelled. It now has `dispose()`, called from `DefaultPlugin.dispose()` through a host-side `DisposableProvider` - not on the api interface, which would be an api release for a lifecycle no plugin participates in (#223)
- **browser**: the page event bridge is never left on `window`. It goes in under an unguessable per-injection name, is passed to the plugin's script as a parameter, and the slot is deleted in the same evaluation - so a page has nothing to replace (intercepting the credential the script posts), nothing to call (forging events into the plugin's sink) and no stable "this is BOSS" key to enumerate. `putProperty` and the evaluation are separate IPC calls, so the random name closes the window between them, and a throwing evaluation deletes the slot rather than leaving the bridge reachable (#222)
- **browser**: `PageEventBridge` caps payload size and rate, following `BrowserInteractionBridge` - every accepted string is an allocation in the host JVM and an item into the sink's queue. Over-sized payloads are rejected before the rate budget is touched, or a page could spend a whole window on strings that were never going to be forwarded (#222)
- **browser**: `emit` no longer swallows Throwable in silence. The sink is a plugin closure from a hot-swappable classloader, so a stale `NoSuchMethodError` is live rather than theoretical and it killed the credential channel with nothing in any log. `LinkageError` and `Exception` are reported separately, with one rate-limited debug line naming the exception *class* - never the payload, which may be a plaintext secret (#222)
- **ui**: the alert body gets a `space.md` gutter while the scrollbar is showing; before, the bar sat on top of the last characters of every wrapped line. Also 18 dead imports removed from `BossDialog.kt`, left behind when the card moved out (#219)
- **docs**: the README calls the atlas plugin fluck-agent, following the plugin's own rename. Every other "Atlas" in this repo is ChatGPT Atlas, the competitor browser the Speedometer benchmarks measure against, and stays as it is (#220)
- **quality**: `DesktopLogCaptureTrimTest` asserts the ratio of capturing into a full buffer versus an empty one rather than a wall-clock bound - a first attempt bounded 30k lines at 20s and passed against the bug it was written for, because per-line stdout cost swamps it and varies by machine. Measured either side: 5.1x with the `size()` trim, 0.9x with the counter (#223)
- **quality**: the coalescing tests count `rebuildCount` at the source. The first version sampled `logs.value` from a watcher thread and *passed* against the per-line rebuild - StateFlow conflates, and 2000 rebuilds finish inside a millisecond, so neither polling nor collecting can count them (#223)
- **quality**: `InjectJsCallbackOwnershipTest` pins the single-owner rule by reading the source, because the failure mode is a second call site rather than a behaviour a test could observe without a real Chromium. It walks the whole tree, not just `composeApp/desktopMain`, and its comment stripper no longer cuts a line at the `//` in `https://` (#222)
- **quality**: `PageEventScriptsTest` pins the injection wrapper's parameter name, its read-then-delete order and that nothing touches `window` under the published name, because contract drift there is invisible - a plugin written to the old shape gets `undefined.emit`, a swallowed TypeError, and no events ever (#222)

## Dependencies

- `boss-plugin-api` 1.0.80 → 1.0.83. Not what makes the new method compile here (`plugin.browser` is a host source mirror) - it is because fluck-browser declares `minApiVersion 1.0.83` and the host refuses a plugin asking for more api than it serves (#222)
- `plugin-ui-core` 1.0.9 → 1.1.0. The signature is unchanged but the contract for an existing argument is not, and a behaviour-breaking change to a published artifact should not read as a patch (#219)

## Known Limitations

- **Two tabs on one URL are still resolved by iteration order.** Nothing ties a handle to the tab that owns it, so `findBrowserForTab` can hand back the wrong one. Behaviour is unchanged - first match still wins - but the ambiguity is now logged with its count, because the symptom otherwise is a plugin driving a page the user is not looking at with nothing to say so. Closing it needs the tab id at browser-creation time, and `BrowserConfig` does not carry one (#223)
- **`lastKnownUrl`'s seeding and update are not covered by tests.** `BrowserHandleImpl` needs a JxBrowser `Browser`, there is no mocking library on this source set, and that interface is far too wide to stub by hand - the same reason no test constructs a handle today (#223)
- **A page event script may be evaluated more than once in one document, and must tolerate it.** A one-evaluation-per-document guarantee was attempted and withdrawn: `NavigationFinished` fires *after* the document-start injection, so the generation counter advanced between the two injections that can reach one document and the second was always allowed. It prevented nothing (#222)
- **The org publish path cannot reach the BOSS store, structurally.** `@boss` is `is_system` and the list the org path authorises against drops system organisations, so naming it explicitly is a 403 even where its own policy would admit the caller, naming nothing is a 403 rather than a silent fallback, and a plugin already recorded against boss cannot be versioned through the org path (#221)
- **Authorship is untouched.** Every version route still refuses `plugin.author_id != caller`, admins included. Widening that to an organisation's other admins is a separate decision (#221)
- **Which branch the alert card takes on the lightweight `Dialog` path is platform-dependent.** Desktop's `Dialog` hands its content an unbounded height on some platforms and a bounded one on others, so the card flexes its body on Windows and not elsewhere. The tests assert only what holds everywhere - the actions keep their height - and the card's KDoc says not to write one that pins the branch (#219)
