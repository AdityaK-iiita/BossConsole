# BOSS v9.4.16

**Release Date:** 2026-08-18

A documentation-only release. The single commit in `v9.4.15..v9.4.16` adds `docs/release-notes/v9.4.15.md` and its one index row - no application code, no dependency and no build configuration changed, so an installed v9.4.15 has nothing to gain by updating.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **There are no functional changes.** `git log v9.4.15..v9.4.16` is one commit, `📝 Add release notes for v9.4.15`, and its diff is two files: the new notes and a row in the release-notes index. Everything a user would notice - the atomic crash-report publication, the named Supabase realtime clients, the `-PskipLint` build fix and five dependency bumps - was already in the v9.4.15 build and is written up in [v9.4.15](v9.4.15.md), not here
- **The tags sit one commit later than the version bumps they name, which is why this release exists at all.** `v9.4.15` points at `🔖 Bump version to 9.4.16` and `v9.4.16` points at the release-notes commit after it. So `version.properties` already reads `app.version=9.4.16` at the **v9.4.15** tag: a build cut from either tag reports the same 9.4.16 and the two differ only by those two doc files. Worth knowing before matching a reported version against a tag, or before assuming a v9.4.16 binary contains something a v9.4.15 binary does not
- **Publishing these notes is the point of the release, not a side effect.** The notes are pushed to `app_releases.release_notes` and rendered by the in-app update dialog, so v9.4.15's write-up only reaches a user once it is committed - which it could not be until after that release was tagged. That ordering is what turns each release-notes commit into the sole content of the next patch

## Improvements

- **docs**: `docs/release-notes/v9.4.15.md` records the v9.4.15 release - the contained crash report published by atomic replacement instead of being streamed into its final path (#189), the per-client Supabase realtime logging that stops bypassing `BossLogger` for stdout (#201), the `.worktrees/` ignore rule (#202), and `-PskipLint` in place of task exclusions that never excluded the 351 per-source-set ktlint tasks (#203)
- **docs**: the index row in `docs/release-notes/README.md` is added between the `RELEASE_INDEX` markers, keeping the generated table the one place a reader scans for what a version contained

## Known Limitations

- **Nothing is fixed here.** The realtime reconnect loop that v9.4.15 made attributable is still unfixed, and the two near-identical Supabase logging processors still have to be kept in step by hand (#201). Both remain open for a later release
- **The tag offset is not corrected by this release.** It is described above so a reader can account for it; the numbering itself is unchanged, and a future release notes commit will land the same way unless the bump and tag order changes
