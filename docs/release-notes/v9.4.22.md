# BOSS v9.4.22

**Release Date:** 2026-08-20

Three changes: the Settings window is searchable from the nav rail, browser zoom works again on Windows and from the View menu, and `BossAlertDialog` stops squeezing its buttons to nothing in a short window - the same defect as v9.4.21's width fix, on the other axis.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **Search the Settings window.** A field above the nav rail; typing replaces the section list with ranked results, and picking one navigates to the owning section, scrolls to that control and washes it briefly. Settings had grown to 19 sections and around 145 host-owned controls, navigable only by opening them one at a time, with Security at 1000 lines and the Chromium flags at 681 read top to bottom (#218)
- **Browser zoom was a no-op, for two independent reasons.** On Windows the native Chromium child window consumes Ctrl+= / Ctrl+- / Ctrl+0 before AWT or Compose sees them, and unlike Ctrl+R zoom had no case in `FluckEngine`'s native key callback. On every platform the View menu's Zoom In, Zoom Out, Actual Size and Reload gated on `activeTab is FluckTabComponent`, a branch that can never be taken (#217)
- **An alert's actions no longer come out 0dp tall.** A Column measures its non-weighted children in order, so in a window shorter than the content the body took what it wanted and the actions - measured last - were offered nothing. Measured in a 300dp frame, "Don't allow" came out 0dp tall at y=276, on a surface whose whole job is to be agreed to or refused (#216)

## Features

- **settings**: `SettingsSearchIndex` declares every searchable control, keyed by (section, group, label) and never the label alone - Performance carries "Warning Threshold" and "Critical Threshold" twice each and Browser Engine carries "Rendering mode" twice, so a label-only key would navigate to the wrong row and light up both on arrival (#218)
- **settings**: `SettingsSearchMatcher` tokenises the query and scores each token against label, group, section and keywords. The existing `FuzzyMatcher` is a strict subsequence matcher over one string, so `match("user agent", "Browser Identity")` is null - the most natural query found nothing without this. Keyword hits are damped so a curated synonym never outranks a real label (#218)
- **settings**: plugin-contributed pages are merged in at query time from the registry rather than declared, so RBAC and plugin lifecycle are respected for free. No plugin API change (#218)
- **settings**: the Shortcuts tab-switching chips are findable and highlightable - "tab switching", "ctrl+tab", "switch tabs" and "mru" all reach them. Shortcuts was first filed with the delegated sections on the reasoning that it has its own search box, which is not the same thing: `EditableKeymapSettings` is host code and was indexable all along, and that mis-filing also took the page out of the drift guard, so nothing reported the gap (#218)

## Bug Fixes

- **browser**: Ctrl+= / Ctrl+- / Ctrl+0 now zoom on Windows. The missing cases sit beside the reload case and use `KEY_CODE_OEM_PLUS` / `KEY_CODE_OEM_MINUS` - JxBrowser 9.4.0 has no `KEY_CODE_EQUALS` or `KEY_CODE_MINUS`, and reaching for those names compiles fine and then silently never matches, so a test pins the mapping (#217)
- **browser**: the View menu's browser items work again. `registerFluck()` is disabled and the live tab is the dynamic plugin's `FluckBrowserTabComponent`, an unrelated type, so the old type check was dead. `ActiveBrowserRegistry`, populated from `BrowserHandleImpl.Content()`, lets the host name the browser without naming a plugin's class - ranking main-panel over sidebar, active split panel over inactive, then most recently shown (#217)
- **browser**: native zoom interception is gated on rendering mode, not just on OS. The macOS exemption reasoned about `HARDWARE_ACCELERATED` but tested for `!isMacOS`, and `OFF_SCREEN` is reachable per install through `BOSS_RENDERING_MODE` or Settings > Browser Engine - the one mode where the chord arrives through AWT and Compose, so the native case and the AWT keymap could both act on one keypress. `HARDWARE_ACCELERATED` is the default everywhere, so shipped behaviour is unchanged (#217)
- **ui**: in a bounded, too-short card the body takes the flexible space and scrolls while the title and the actions keep theirs. Both qualifiers are load-bearing and both were measured: `fill = false`, because a bare `weight(1f)` fills its share and would stretch every one-line alert to the full window; and the bounded-height branch, because an unbounded card measures 1116dp and renders its body inline, where applying the weight anyway collapses it to about one line for no gain (#216)
- **settings**: the content area's scroll state is keyed on the section. It was shared across every page, so leaving Security scrolled down and clicking Sidebar landed you at the bottom of a short page - odd on its own, and actively misleading once a search hit near the top of a section could be scrolled past before its bring-into-view ran (#218)
- **settings**: the Shortcuts page scrolls its LazyColumn to the tab-switching item when a highlight arrives. A control that is not composed cannot be brought into view, so a chip was unreachable whenever the page was already scrolled down its shortcut list (#218)

## Improvements

- **ui**: `BossAlertCard` is extracted as an internal composable, because none of this is reachable through `BossAlertDialog` in a test - it routes to a platform dialog window, which does not inherit the size of whatever composed it. The flex branch is read from a `BoxWithConstraints` inside the Surface rather than outside it, since the caller's modifier sits between the two and can bound a card whose parent did not (#216)
- **ui**: the body draws its own `VerticalScrollbar` when there is something below the fold (#216)
- **settings**: the highlight is a modifier applied inside the 12 shared controls and the control brings itself into view via `BringIntoViewRequester`. Having the window compute offsets and drive the `ScrollState` would have to solve a race it cannot see: on the frame the section changes, the target does not exist yet, so the scroll runs against the outgoing layout and reports success either way (#218)
- **settings**: `SettingsTheme.kt` moves from desktopMain to commonMain, same package, and the highlight locals and modifiers move to `commonMain/.../settings/search/SettingsHighlight.kt`. The two variants are now named for what they do rather than where they were used - `settingsRowSurface` paints the row surface and takes the wash over it, `settingsSearchTarget` is highlight-only for anything painting its own background (#218)
- **settings**: a source-scanning convention test guards the index in both directions - a section that gains a label the index does not list fails, and so does an index entry naming a label the sources no longer contain. The second is the one that matters, since that is what a rename produces: a result that still navigates and then highlights nothing. The scan now covers the keymap directory too (#218)
- **quality**: `BossAlertCardLayoutTest`, ten cases, each mutation-verified to fail on the change it names - pre-fix layout, `weight(1f)` without `fill = false`, the weight applied unconditionally, `verticalScroll` dropped, the branch read from the outer constraints, and the height cap deleted (#216)

## Dependencies

- `plugin-ui-core` 1.0.8 → 1.0.9. The measurement contract of a published slot changed, so a consumer needs something to pin against (#216)

## Known Limitations

- **The `text` slot is now measured with an unbounded main axis on the bounded path.** `verticalScroll` hands its child `maxHeight = Infinity`, so an uncapped lazy list or nested scroll in a `text` slot will not lay out. Both the 29 `text` slots in this repo and the 12 across `boss_plugins` were audited and every occurrence is capped, but this module is published and cannot bound what a plugin's slot contains. The constraint is documented on the `text` param of both public overloads (#216)
- **A slot that caps itself against its parent loses that reference point.** A cap written as `min(myMax, constraints.maxHeight)` - which is what the host's `dialogScrollFence` computes - coerces against infinity here and always takes its full constant, so on a short window the two fenced dialogs get nested scroll regions instead of a body that shrinks. Content stays reachable; it is a UX regression, not a break (#216)
- **Only the scrimmed path flexes.** The card flexes when its height is bounded, which is the in-window scrimmed path and where the report came from. On the lightweight Dialog path the change is inert and the ceiling is the screen, not the card: a 1116dp card on a shorter display still puts its actions out of reach. Pre-existing, now stated rather than implied away (#216)
- **The four delegated Settings sections are indexed at section level only.** Terminal, BossEditor, Language Servers and AI Providers render panels owned by other modules, roughly 330 labels the host cannot enumerate, so their results carry curated keywords and do not promise a highlight (#218)
- **A Shortcuts chip is reachable on a fresh visit, not mid-scroll in every case.** Bringing a target into view only works once it is composed; the page now scrolls its list to compose the item first, but the LazyColumn constraint itself remains (#218)
