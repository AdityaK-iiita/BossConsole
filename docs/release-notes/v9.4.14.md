# BOSS v9.4.14

**Release Date:** 2026-08-18

A release about features that had never actually worked. Domain verification refused every correct TXT record since the day it shipped, plugin ownership was resolved for nobody so all forty store plugins belonged to the system organisation, two downloads of one name silently overwrote each other, and recycling a wedged browser engine left an invisible Chromium alive - still playing audio - while every open tab died with it.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.0 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **Domain verification could never complete.** "Verify now" answered "The change was refused." on every domain whose record was correct. The DNS probe was fine; the write after it named a signature the database does not have - `callForActor` appends `p_actor_id` to every call, and this one RPC takes `p_verified_by` instead, so PostgREST failed to resolve it and the transport error surfaced as a generic refusal. The failure was only reachable *after* a successful DNS check, so it appeared exactly when the operator had done everything right. 159 tests were green throughout, because the RPC stub keys on the function name and ignores the parameters entirely (#190)
- **Every plugin in the store was attributed to `@boss`.** `createPlugin` never set `org_id`, so the default trigger resolved the system organisation for every row - including the publishing API key's own `org_id`, which the validator returns and the auth layer discarded. Ownership was inert, since `@boss` is the organisation every signup joins. `resolvePublishOrg` decides it now, most explicit first, and **every** branch that produces an organisation is authorised against `user_can_publish_org_plugin` - the publish path runs as service role, so the RLS `WITH CHECK` on `plugins` is bypassed and nothing else would refuse it (#196)
- **Each plugin has a page: its README, who owns it, and Open or Install.** `/o/:slug/plugins/:pluginId` renders the README as Markdown from GitHub - escaped *before* any formatting rule runs, so a `<script>` in somebody else's repository is text no matter what the renderer does with it - beside a visibility control for admins of the owning organisation. `plugins.visibility` has existed with three values since the multi-tenancy work and nothing had ever written one (#197)
- **A recycled browser engine left live browsers and processes behind.** A browser could be stamped with a generation it does not belong to, so `isValid` answered true forever and the first call through it threw at whichever plugin made it; a `close()` that threw on dead IPC counted as one that worked, so the force-kill was skipped precisely when needed; the kill deliberately skips this JVM's own children, which is exactly what the engine being recycled is; and the replacement booted before the old process released `--user-data-dir`, falling back to a throwaway profile that signed the user out of every site (#200)
- **Two downloads of one name overwrote each other.** A download's file is not created until bytes arrive, so `exists()` answered "free" to both callers. Paths are claimed when handed out and released on any terminal state, the Downloads panel records the name the file was actually written under rather than the one that was requested, and the uniqueness counter no longer returns the occupied path it gave up on (#199)

## Features

- **organisation**: "Add N existing users" beside a verified domain adopts every confirmed account at that domain as an active member. A verified domain previously only ever let a user *choose* to join, so deploying BOSS across a company meant every colleague finding it themselves. Authority is the DNS proof plus org-admin, checked against the domain's own organisation - nothing in the parameter list names an org, so there is none to substitute. Reserved domains are refused, unconfirmed addresses skipped, and anyone with an existing membership row in *any* status is left alone: a pending applicant is not promoted, an invited user is not auto-accepted, and somebody an admin removed is not re-adopted by the next press (#190)
- **organisation**: the DNS verification record splits into Name / Type / Value with a copy button on the two worth copying. It rendered as one span before, which reads fine and is useless to the person holding it - every registrar asks for host and value separately, and selecting part of a long token with a mouse is where a truncated record comes from. The value is carried in `data-copy` rather than read from the element's text, so wrapping cannot start handing out broken records (#190)
- **organisation**: a public plugin's page needs no session. Handing one to these pages needs `mint_organisation_handoff_token`, which is members-only, so a Toolbox link would have resolved only for plugins owned by an organisation the reader had joined - and almost no reader is in `boss` or `risa`. The widening is exactly "ask the RPC with a null viewer": `user_can_view_plugin_row`'s anonymous arm is `public AND published`, which is what the Toolbox already reads anonymously, so no row becomes visible that was not already (#197)
- **organisation**: Open in BOSS / Install on a plugin page. The page is served by an edge function and cannot see anyone's machine, so the Toolbox tells it through `installed=1` or `0` - a hint that only a label depends on, since the deep link carries the plugin id and lets the app decide. Absent is a third state, not a synonym for "not installed", so somebody arriving from a shared link is told what BOSS will do rather than invited to install something they may already run (#197)
- **organisation**: the members and plugins tables are paged at 25 rows, with the pager omitted when everything fits - a control saying "1 of 1" beside three rows is noise pretending to be information. Both page numbers travel in every link, so paging through members does not send the plugins table back to page one. Links, not buttons, and no script, under a nonce-only CSP (#197)
- **plugin-store**: `/list` answers per reader, so members see their organisation's plugins. `search_plugins` reads `auth.uid()` and the handler holds a service-role client, so the answer was computed for nobody and the list was public-only for everybody - an `org`-visibility plugin was invisible to the very members it exists for. Identity is optional on purpose: browsing a store is not a privileged act, so a missing, expired or malformed token yields the public catalogue rather than an error. An API key is deliberately not accepted as identity here (#196)
- **plugin-store**: publishing API keys bind to their owner's single non-system organisation, so a CI publish attributes correctly. `orgId` is accepted on all three publish schemas (#196)
- **browser**: the page's own file dialogs use the OS panel. Clicking an upload field opened a Swing `JFileChooser`, which on macOS renders the pre-10.7 Open panel with a "Where:" popup, while Safari and Chrome open the real `NSOpenPanel`. Nothing in BOSS chose that - JxBrowser installs default callbacks at view creation and every file-related one shows a chooser, and we never answered the five callbacks ourselves. `NativeFileDialogs` answers all five with `java.awt.FileDialog`, registered at browser construction so it survives a view being detached and re-attached, and popup browsers are covered too - an OAuth or payment popup is exactly where an upload field turns up (#198)
- **panel**: files dropped on the main panel open, routed by extension through the same `openFileInActivePanel` a sidebar click uses - images and PDFs to the browser, `.ipynb` to the notebook tab where that plugin is registered, everything else to the editor. No new routing rules, so a drop and a click cannot disagree. The transfer type is plain `DataFlavor.javaFileListFlavor`, which is the point: the same target already accepts a drag out of Finder or Explorer, with no BOSS-specific type a plugin would have to know about (#199)

## Bug Fixes

- **organisation**: Configure said "Session expired" from a cold start. Only `/o/:slug` consumed the handoff token; `/o/:slug/admin` went straight to the session guard and found no cookie, so Configure never worked on its own - it appeared to, if you pressed Open page first and rode the cookie that navigation left behind. The exchange is extracted and called from both routes, running *before* the guard, with the slug validated here since it is about to be built into a `Location` header. 7 of its 9 tests fail against the previous version; the suite had 179 passing while the button was broken (#190)
- **organisation**: the plugin page 404'd for everybody. `get_plugin_with_stats_for_viewer` is `RETURNS TABLE`, and PostgREST answers a set-returning function with a bare JSON array that has no `success` field - so `callRpc` failed closed, correctly, and the page answered 404 for every plugin that exists and is visible. Found by review before deploying, not by any test: the view tests render a fixture and the pgTAP tests exercise the SQL, so the one step between them was the only thing uncovered. `callRpcRows` is a separate helper rather than a relaxation of `callRpc`, and fails closed the other way (#197)
- **organisation**: `list_org_plugins` returned its rows under a key called `plugins`, so the desktop plugin's Plugins tab reported "Something went wrong" for a call that had succeeded. Every other org RPC returns `{success, data}` and both shared decoders say so in their own words. The edge function was written against the odd key at the same time as the function, so nothing noticed - a convention only holds where something reads it, and one caller written alongside its own producer proves nothing (#197)
- **organisation**: the visibility warning said something no longer true. It claimed restricting a plugin removes it from the Toolbox "for everyone", which was accurate when the Toolbox read its catalogue anonymously and stopped being accurate this release. It now says what happens: gone from the public listing, still found by members, and invisible to anyone on an older Toolbox - which is the part still worth warning about (#197)
- **auth**: `validate_plugin_api_key` was recreated as `RETURNS TABLE(key_id, user_id, scopes, org_id)` in an earlier migration while `utils/auth.ts` still read `api_key_id` and `key_name`, so `apiKeyId` has been undefined ever since - `update_api_key_last_used` was called with `p_key_id: undefined` and every `if (user.apiKeyId)` audit-log call silently no-opped. API-key publishes have not been audit-logged at all. The test stub returned the old column names too, so it agreed with the stale reads and both were wrong together (#196)
- **browser**: a browser could be stamped with a generation it does not belong to. `attemptCreateBrowser` read the engine first and the generation last, with a 20s time-boxed `newBrowser()` between them - the exact window a recycle fires in, since the recycle is triggered by these creations failing. `Browser.isClosed` stays false for a browser whose engine died with its IPC channel, because the notification that would flip it has no channel left to arrive on, so `isValid` answered true forever and no tab recovered. Both values are read in one step now (#200)
- **browser**: a `close()` that failed counted as a close that worked. The force-kill ran only when `close()` failed to *return* within 5s, but a wedged engine's `close()` throws immediately on dead IPC and `runCatching` swallowed it. What matters is whether Chromium is gone, so that is what is asked - of the OS, not of the return value (#200)
- **browser**: the kill could not have killed it anyway. `killStaleChromiumProcesses` deliberately skips any process parented to this JVM so a sweep cannot take out the live engine, and the engine being recycled is exactly such a child. The doomed processes are snapshotted under `engineLock` before the generation bump, when no replacement can exist, and killed directly - descendants first, since killing the parent reparents them to pid 1 where nothing can reach them, and SIGKILL after SIGTERM (#200)
- **browser**: the replacement booted into the wreckage. Tabs came back through the engine getter about 400ms after the generation bump, long before the old process released `--user-data-dir`, so creation hit `UserDataDirectoryAlreadyInUseException` and fell back to a throwaway `browser-profile-<millis>` directory - signing the user out of every site they were signed into. A boot now waits, bounded, for the engine it replaces to drain (#200)
- **downloads**: the panel showed the wrong name. `generateUniqueFilePath` may append " (1)" and the save dialog lets the user type whatever they like, so the suggested name is only ever a request - but the request is what was recorded, and a file written as "report (1).pdf" was listed as "report.pdf" with Reveal and Open following the label (#199)
- **downloads**: the uniqueness counter overwrote the file it exists to protect. `while (exists() && counter < 1000)` leaves the loop with the path still occupied once it gives up, and that path was returned and written to. It retries until a claim succeeds instead, over a documented 1..999 range (#199)
- **downloads**: a claim had no owner, so the save-dialog path disarmed the protection for the auto path. `releaseFilePath(path)` removed whatever was there, and the dialog returns whatever name the user typed - which can be a path the auto path is already holding - so that download's terminal handler released a claim it never took and a third download could take a path still being written to. A claim records its owner now and only the owner can give it back. Claims are also self-healing: nothing guarantees a terminal event, so a claim whose file still does not exist after ten minutes is treated as abandoned rather than pushing every later download of that name onto a suffix for the life of the process (#199)
- **downloads**: claim keys are case-folded. APFS and NTFS make `report.pdf` and `Report.pdf` one file but they were two claims, and the name comes from a server-supplied `Content-Disposition` (#199)
- **panel**: a dropped folder no longer opens an editor tab on a directory. Finder hands folders over through the same flavour as files and the caller routes by extension, so "a drop and a click cannot disagree" was false for them. They are filtered with a log rather than guessed at as a working-directory drop, and a drop is capped at 20 files so one select-all does not open 20-plus LSP sessions (#199)
- **browser**: Windows was a net regression on the native file dialog, in two ways that both fail silently, so `isSupported` is macOS only. `FileDialog` cannot select a directory outside macOS - there is no equivalent of `apple.awt.fileDialogForDirectories`, so `webkitdirectory` would have handed Chromium a *file* path, where the chooser it displaced used `DIRECTORIES_ONLY` and worked. And `setFilenameFilter` is documented as a no-op there, because the Win32 peer drives `GetOpenFileName` with filter strings rather than a per-item callback, so an `accept=".png"` input would have listed every file (#198)
- **browser**: the accept filter was more restrictive than the page asked for. Dropping the MIME tokens from `.png,image/*` and filtering on the surviving `png` greyed out `photo.jpg`, which that input explicitly allows - so a mixed list was narrower than no filter at all, and `OpenFiles` could not escape it because `acceptAll` is hardcoded false there. A token that is not a suffix now makes the whole filter unrepresentable rather than just itself (#198)
- **browser**: a modal `FileDialog` pumps queued `invokeLater` blocks, so a second dialog really can be created inside the first one's loop with the directory-mode property still set. Every dialog states its own mode immediately before showing and restores by clearing rather than writing "false", so nesting unwinds correctly (#198)
- **browser**: `answerOnce` catches `Throwable` rather than `Exception`. An `AWTError` from peer creation would otherwise escape the `invokeLater` body and leave the input pending for the life of the tab, which is the one thing that function exists to prevent - `Error` is still answered and then rethrown (#198)
- **browser**: the pre-filled save name no longer goes through `FileNameSanitizer`, which maps non-ASCII to underscores - a page titled in Japanese pre-filled as `___.pdf`. Nothing here needs to be filesystem-safe, since the returned path is what the panel reports back. Save-as-PDF also appends `.pdf` when the user clears it off the name, and `safePrefill` no longer passes "." and ".." through as names (#198)
- **browser**: the native dialog peers are disposed. These are page-driven and repeatable, unlike the one-shot pickers elsewhere that leave theirs to finalization, and the panel is owned to a `Dialog` as well as a `Frame` - falling back to a null owner while a BOSS modal is up is exactly the case the owner exists to fix (#198)

## Improvements

- **plugins**: the six RISA plugins are attributed to the `risa` organisation by migration - named, not derived, because `plugins.author_id` is whoever ran the publish and is the same person for most of this store, so deriving would sweep up plugins that are not RISA's. Bounded to rows still on `boss` or NULL, idempotent, reporting MOVED / SKIPPED / ALREADY per plugin rather than a count, since a typo'd id would otherwise be indistinguishable from a successful no-op in the deploy output. Access is unchanged and asserted rather than argued: `can_view_plugin_row` short-circuits on public-and-published before it reads `org_id` (#196)
- **organisation**: the README is rendered as Markdown with no library, because every general renderer passes raw HTML through by design - which on a page that also carries an admin visibility control would leave the CSP as the only thing between the two. Raw HTML shows as text, only http / https / mailto become links, images render as links rather than `<img>` (allowing them would let a publisher log every reader of their plugin's page by URL), and a relative link keeps its text and loses its href since it would resolve against this function's own origin (#197)
- **organisation**: the source repository and the icon go through `attrUrl` rather than `esc` alone. `homepage_url` is publisher-supplied, so `javascript:alert(1)` would have become a working link - there is nothing in it for `esc` to escape. The README fetcher matches the `github.com` hostname exactly and never `includes("github.com")`; without that, the page is an SSRF probe pointed by whoever published the plugin (#197)
- **organisation**: READMEs are memoised per isolate for ten minutes, failures included. Every render was one outbound GitHub call and the page can now be requested by anyone as often as they like, on a `GITHUB_TOKEN` shared with the plugin-store's github service. Caching only successes would have left the cheapest case - a private or missing repository - re-asked every time, which is the case an attacker would choose (#197)
- **organisation**: `Cache-Control` is `private, no-store` once a viewer is known, since the same URL now returns different rows per reader and a shared cache holding one reader's copy would serve their organisation's plugins to the next caller. Anonymous keeps `public, max-age=60` (#196)
- **tests**: `rpc-signatures.test.ts` is a sweep rather than a case. Every `callForActor` target is checked against the parameter names the migrations give it, latest definition winning, with a floor assertion so a wrong path cannot make the sweep iterate over nothing and pass - it parses 125 functions against a floor of 30. It also refuses a `callRpc` call site pointed at a `RETURNS TABLE` function and the reverse, and its call-site regex is lazy now, because it could not cross a nested generic and had been silently skipping `callForActor<Record<string, unknown>>(...)` (#190, #197)
- **tests**: `FileSystemUtils` had no tests at all. `filePathsOrEmpty` is extracted and tested over a fake `Transferable` - unsupported flavour, a throwing source, null data, a `List<String>` that passes `as? List<File>` and fails inside the map, folders, and the cap - alongside ownership and case-folding, and the exhaustion fixture no longer writes content to 999 files (#199)
- **tests**: the JxBrowser behaviour the file-dialog fix rests on is pinned on both halves - a default callback does not replace one already set, and `unregister()` removes a type only when the currently-set callback is the one it registered. The second half needs no library upgrade to bite: `FullscreenBrowserWindow` builds and disposes a Swing view over a live browser on every fullscreen toggle (#198)
- **tests**: the process-kill tests skip on Windows rather than being ported. What they pin is POSIX behaviour with no counterpart there - an orphan keeps its recorded parent id, and `destroy()` and `destroyForcibly()` are both `TerminateProcess`, which cannot be trapped, so there is no escalation to observe. Uses the `assumeTrue` idiom already in `UpdateScriptGeneratorHardeningTest` (#200)
- **tests**: 467 pgTAP assertions across the suite pass against a fresh `db reset`, plus 188 Deno tests. Guards were measured by deleting each and re-running rather than by reading - dropping the admin gate on domain adoption fails 3 assertions, the verified check 4, the confirmed-address filter 3, the reserved-domain backstop 1 - and the three layers protecting an existing member are recorded as asserted-in-behaviour but not individually covered, because in a single session the other two mask each one (#190, #196, #197)

## Known Limitations

- **Existing plugin rows are not re-attributed beyond the six named.** Ownership is resolved only when a plugin is *created* - a new version must never re-derive it, or a plugin would migrate between organisations as its publisher's memberships changed. `routes/api-keys.ts` still does not set `org_id` on creation, so a new key is NULL and coalesces to `boss` until it is bound elsewhere (#196)
- **The Toolbox does not send `orgId` and has no organisation picker.** The mechanism is in place; nothing yet uses it (#196)
- **Table paging happens in the view, after the RPC has returned every row.** `list_organisation_members` and `list_org_plugins` still have no `LIMIT`. What this buys is a readable page, not a smaller query (#197)
- **The Open in BOSS button is swallowed inside BOSS's own browser**, which is web-schemes-only. It works from an external browser; closing the gap is a fluck-browser change (#197)
- **Windows still gets the Swing chooser for a page's file dialogs.** Both regressions are worth fixing, but with Win32 filter strings and a folder browser rather than by pointing Windows at `FileDialog`. Linux keeps the JxBrowser default deliberately: AWT there uses `GtkFileDialogPeer` only when GTK loads, and otherwise falls back to a Motif-era dialog worse than the chooser it would replace. The auth browsers are not covered either (#198)
- **Drop hover feedback and cross-application drag interop are not addressed.** The latter needs a real drag rather than an assertion (#199)
- **Treating a dropped folder as a working-directory change is not invented here.** Folders are filtered and logged (#199)
