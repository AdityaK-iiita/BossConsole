# BOSS v9.4.36

**Release Date:** 2026-08-26

Three changes, all about what actually ships. The desktop package loses roughly a third of its size to things no user could ever run - a JDK toolchain, locale data for languages BOSS has no text in, other platforms' native binaries, an icon pack with zero call sites - the bundled-plugin build stops shipping a 1 MB stand-in for a 4 MB browser plugin and stops deleting the terminal it had just downloaded, and the host's second, view-only code editor is gone along with the `editor_write_file` MCP tool's infinite recursion.

> **macOS 13.0 (Ventura) or later is required**, unchanged from v9.4.0 - the bundled JxBrowser 9.4.1 engine declares `LSMinimumSystemVersion 13.0`.

## Highlights

- **The download is a third smaller.** Measured end to end on macOS arm64: shipped 9.4.33 was 293.4 MB and this build is 191.2 MB, with the installed footprint going 402 MB to 268 MB. Nothing user-facing was removed - the savings are the JDK's developer tooling (-17 MB), `jdk.localedata` (-33 MB), other platforms' natives inside skiko and sqlite-jdbc (~-19.5 MB), the unused font-awesome pack (-5.1 MB) and unbundling the 64.7 MB editor-tab seed that the system-plugin store already fetches anyway (#260)
- **The terminal has never actually been bundled, and now is not by accident.** `downloadBundledPlugins` removed old versions with a bare `startsWith(artifactPrefix)`, and `boss-plugin-terminal` is a prefix of `boss-plugin-terminal-tab-2.5.59.jar` - so every build downloaded the 35 MB terminal-tab plugin, deleted it one iteration later as an "old version", and finished green. The cleanup now requires the version separator (a hyphen followed by a digit), which is what turns a prefix into a name boundary (#261)
- **fluck-browser shipped its thin JAR.** A plugin release publishes `<prefix>-<version>.jar` with dependencies bundled and `<prefix>-<version>-thin.jar` without them; the build-side picker used `Regex.find`, taking whichever asset GitHub listed first, which for fluck-browser is the thin one. Every bundle up to and including 9.4.33 carried 1 MB standing in for a 4 MB plugin. The picker is now character-for-character the host's own `pickPluginJarUrl` rule, which the store had right all along (#261)
- **The host's second code editor is deleted.** 786 lines of `CodeEditorUI`, its own Kotlin keyword list, syntax highlighter, gutter, font and colour hooks and tab component, sitting beside editor-tab, which bundles BossEditor and owns every editing surface in the product. Its registration had been commented out in two places and its own KDoc called it "effectively VIEW-ONLY" - the one reachable path accepted `onSaveRequested`, `onModifiedStateChange` and `onRunFunction` and discarded all three (#262)

## Bug Fixes

- **editor**: `editor_write_file` stack-overflowed on every call. `EditorContentProviderImpl.writeFileContent` was written to delegate to the top-level function of the same name, but Kotlin resolves a member of the implicit receiver ahead of a top-level - import or not - and the signatures were identical, so the call bound to itself. The top-level is `writeFileContentSafe` now, matching `readFileContentSafe` next to it, which makes the fix durable: a top-level whose name and signature match an override in its only caller is unreachable by construction. `readFileContent` was never affected (#262)
- **build**: a bundled plugin removed from the list still shipped. The list was a literal inside `doLast`, invisible to Gradle, so editing it invalidated nothing and a warm build directory went UP-TO-DATE without running; and the per-plugin cleanup only ever fired for prefixes still in the list, so nothing removed the JAR of a plugin that left it. Reproduced by planting a de-listed `boss-plugin-editor-tab-1.4.20.jar` and watching `Sync` faithfully copy all 64.7 MB into the package. The list is an `inputs.property` now and JARs belonging to no listed plugin are pruned, boundary-aware for the same reason as above (#260)
- **build**: a directory holding both the real JAR and a leftover thin one kept the thin one forever, because the already-have-it `continue` fired before any cleanup ran. Cleanup moved ahead of that check and taught to skip the file it is about to keep (#261)

## Improvements

- **build**: a release now fails when a bundled plugin is missing. Every path out of the download loop was warn-and-continue - a 403, a repo with no release, an asset regex matching nothing, a cleanup deleting the wrong file - and nothing ever asserted the directory was complete, which is why both bugs above lasted as long as they did. On CI that is a `GradleException`, since `prepareBundledPluginsResources` only routes there when `CI == "true"` and a release going out without plugins it promises is worse than a failed build. Locally it stays a warning: a developer may have no network, and `copyBundledPluginsLocal` is their normal path anyway. Adding a new plugin to the list now means publishing it first, which is the intended trade (#261)
- **build**: making the task actually run picked up releases the stale directory had been pinning - api 1.0.84 to 1.0.86 and plugin-manager 1.9.21 to 1.9.24, both frozen at whatever version was downloaded first (#260)
- **build**: the runtime image's module list is deliberately *not* jdeps-minimal. jdeps sees only static references, so a minimal list silently drops what is reached through ServiceLoader or reflection - crypto providers, charsets, the zip filesystem, JNDI backends - and the failure lands on a user's machine rather than in CI. The list uses `java.se` rather than an enumeration of `java.*`, and every `jdk.*` entry is annotated with the consumer that keeps it. `jdk.compiler` stays conservatively, because editor-tab's kotlin-compiler-embeddable ships 96 classes linking against `com.sun.tools.javac` (#260)
- **build**: the native-stripping task is fail-safe in both directions. sqlite-jdbc is left completely untouched unless the native this platform is believed to need is actually present, so a mis-detection costs 10 MB rather than every SQLite read; skiko drops only entries matching a native-library name for a platform other than this one. It is ordered before `signPty4jBinaries` and `extractCLIToAppResources` so the macOS re-sign seals the trimmed jars rather than jars that change underneath it (#260)
- **editor**: the file I/O that editor-tab reaches through the provider survived the deletion in `providers/EditorFileIo.kt`, unchanged - `readFileContent`, `writeFileContent` and `detectLanguage` are the `editor_read_file`, `editor_write_file` and `editor_detect_language` MCP tools. `CodeEditorContent` itself cannot be dropped (it is abstract on `EditorContentProvider` in the `boss-plugin-api` repo, so removing it would break that chain) and now renders one line naming the plugin that owns the editor, which is strictly better than an editor that pretends to save (#262)
- **editor**: `GutterRunIcon` and `GutterRunIconSpacer` go too - their single caller was the run gutter inside the deleted `CodeEditor.kt`, and `composeApp` is the application rather than a published library, so no plugin can reach them either. 140 more lines (#262)
- **tests**: `EditorFileIoTest` covers the round trip, parent-directory creation, FileNotFound and FileTooLarge, going through the provider so the mapping onto the plugin-api `FileReadResult` is covered as well. The first two fail with `StackOverflowError` against the previous commit, which is the point (#262)
- **detekt**: net 14 fewer baseline suppressions - 15 died with the deleted editor files and 1 was added for the relocated I/O, then one more with the gutter icons (#262)

## Dependencies

- Removed `br.com.devsrsouza.compose.icons:font-awesome`. `FontAwesomeIcons` appears exactly zero times in the repository outside the dependency declaration itself, and the artifact landed in the packaged app as a 5.1 MB jar. feather (4 icons used) and simple-icons (143 used) stay (#260)

## Known Limitations

- **Localized month names in three date labels become English.** `jdk.localedata` is gone, and BOSS ships no localized text - no `ResourceBundle`, no localized `composeResources`, every label an English literal. The whole blast radius is five `Locale.getDefault()` call sites: `SecuritySettings.kt` formats three dates, which previously rendered localized month abbreviations next to English UI text and now render English ones, and `UpdateInstaller.kt` lowercases `os.name`, which wanted a locale-independent lowercase all along (under a Turkish default locale the dotted I became dotless and the match silently failed). CLDR root plus `en` stays in `java.base`. If BOSS ever ships localized UI, add `"jdk.localedata"` back in the same commit as the first translated string (#260)
- **editor-tab and terminal-tab are no longer seeded into the bundle.** Both are fetched by `PluginStoreSetup.ensureSystemPluginsInstalled()` from their latest GitHub release before load, so the store is the primary mechanism and the bundle was only a seed that let the download be skipped on a first launch with no network. terminal-tab has been absent from every shipped bundle for months, so restoring it would ship 35 MB to put users into a state none of them has ever been in. api, plugin-manager, fluck-browser, bookmarks and terminal stay bundled - ~7 MB together, and unbundling the Toolbox would leave a failed first-launch download with no interface to recover with (#260)
- **`jdk.compiler` and its 7.9 MB `lib/ct.sym` are still shipped.** Dropping them is a measured further 15 MB, held back until Kotlin analysis in the editor is confirmed to work without the `-Xuse-javac` path (#260)
- **`copyBundledPluginsLocal` still copies a locally built terminal-tab.** That path is a plugin-developer convenience for testing local builds, not a release seed (#260)
